# ADR-0037: 댓글 상자와 본문 마감

- 상태: 채택
- 날짜: 2026-09-05
- 관련: ADR-0021(giscus 댓글), ADR-0027(본문 읽기), ADR-0030(번개 밑줄), ADR-0034(태그 필터 제거)

## giscus 상자를 말풍선으로

giscus 는 다른 출처의 iframe 안에서 돈다. DOM 은 건드릴 수 없지만 우리가 넘기는 테마 CSS 는
그 안으로 주입되므로 CSS 만으로 손볼 수 있다. 클래스 이름은 추측하지 않고 위젯을 직접 열어
DOM 에서 뽑았다 — `.gsc-comment-box`(form) · `.gsc-comment-box-tabs` · `.gsc-comment-box-main` ·
`.gsc-comment-box-textarea` · `.gsc-comment-box-textarea-extras` · `.gsc-comment-box-buttons .btn`.

- **말풍선 꼬리** — 상자 위쪽 왼쪽에 단다. 바로 위의 `comments` 제목과 안내 문구를 가리켜
  "여기서 말하면 된다"가 형태로 읽힌다. 댓글 하나하나에는 달지 않는다 —
  giscus 는 작성자 얼굴을 상자 **안** 머리줄에 두므로 밖을 가리킬 대상이 없다
- **안쪽 이중 테두리 제거** — giscus 는 textarea 와 그 아래 안내 줄에 GitHub 의 `form-control` 을
  붙여 상자 안에 상자가 하나 더 생긴다
- **초점** — 테두리만 악센트로

### 번개 밑줄은 넣었다가 뺐다

글 쓰는 칸 아래에 링크와 같은 번개 밑줄을 그어 봤다. 실제 giscus 위젯에 CSS 를 주입해
높이 9·14·18·24px 로 비교했는데, **어느 높이에서도 660px 짜리 상자에서는 타일이 열 번 넘게
반복돼 벽지가 됐다.** 이 장치는 짧은 글자 아래에서 "지나간 자국"으로 읽히는 것이지
넓은 면을 채우는 무늬가 아니다. 초점 신호는 테두리 색만으로 충분하다.

## 본문 마감

- **절 링크** — 제목에 마우스를 올리면 `#` 이 나타난다. 목차가 쓰는 것과 같은 id 라
  절 하나만 골라 공유할 수 있다. 호버가 없는 기기에서는 늘 보여 준다 —
  호버로만 드러나는 것은 그런 기기에서 없는 것과 같다
- **바깥 링크 화살표** — 이 사이트 안의 링크는 모두 상대 경로라 `http` 로 시작하면 바깥이다.
  누르기 전에 "여기서 나간다"를 알 수 있어야 한다. CSS 선택자 하나로 끝나 자바스크립트가 필요 없다
- **각주** — 본문 뒤에 작은 글씨로 모이고 번호를 누르면 제자리로 돌아간다.
  안내 문구는 우리말로 바꿨다(기본값은 "Footnotes")
- **키보드 키(`kbd`)** — 단축키를 적을 자리

## 테마 CSS 가 안 실리면 댓글이 통째로 사라진다

다크에서 댓글이 하나도 보이지 않는다는 제보를 받고, 세 경우를 나란히 재 봤다.

| 상황 | `data-theme` | 글자색 |
| --- | --- | --- |
| 커스텀 CSS 로드 실패 | `custom` | `rgb(0, 0, 0)` |
| 내장 `noborder_dark` | `noborder_dark` | `rgba(235,235,245,.86)` |
| 우리 CSS 정상 로드 | — | `#dfe2e5` |

**giscus 는 커스텀 테마 CSS 를 못 불러오면 색 변수를 하나도 적용하지 않는다.**
그러면 글자색이 기본값인 검정이 되는데, 흰 배경에서는 우연히 읽히고 검은 배경에서는
아무것도 보이지 않는다. 반응 팝오버는 배경까지 투명해져 뒤 내용이 비쳤다.
라이트가 멀쩡해 보인 것은 고쳐져 있어서가 아니라 **검은 글자가 흰 배경 위에 있었기 때문**이다.

파일 하나가 안 오면 댓글이 통째로 사라지는 구조가 문제다. 주소를 넘기기 전에
같은 출처로 파일이 실제로 있는지 확인하고, 없으면 내장 테마로 물러난다.
우리 색은 잃더라도 댓글이 안 보이는 것보다는 낫다.

`--color-canvas-overlay` 를 덮지 않고 있던 것도 함께 고쳤다. 반응 팝오버가 이 변수를 쓰는데,
우리가 덮지 않으면 정상 로드 때도 기본 테마 색이 남아 어긋난다.

## 테마를 바꿔도 댓글이 따라오지 않던 문제

로드된 라이브러리 코드를 직접 읽고 원인을 정했다. 두 가지가 겹쳐 있었다.

```js
// giscus 웹 컴포넌트
sendMessage(e) {
  !this.iframeRef?.contentWindow || !this.hasLoaded || postMessage(...)  // ← 로드 전이면 버린다
}
requestUpdate(name) {
  if (!this.hasUpdated || name === "host") { super.requestUpdate(...); return; }
  this.updateConfig();   // ← 첫 렌더 뒤에는 iframe 을 다시 그리지 않는다
}
```

1. 첫 렌더 이후 속성이 바뀌면 iframe 을 다시 그리지 않고 postMessage 로만 알린다
2. 그 메시지는 iframe 이 아직 로드되지 않았으면 **조용히 버려진다**

우리는 `loading="lazy"` 를 쓴다. 댓글은 글 맨 아래에 있으므로 글 위쪽에서 테마를 토글하면
iframe 이 아직 없고, 변경은 사라진다. iframe 의 `src` 에는 처음 테마가 박혀 있어
나중에 로드돼도 옛 테마로 뜬다.

`key` 에 테마를 넣어 테마가 바뀌면 위젯을 새로 만든다. 새로 만들면 `src` 에 지금 테마가
담긴 채로 뜨므로 이 경로를 아예 타지 않는다. 대가는 테마를 바꿀 때 댓글이 다시 불러와지는
것인데, **가끔 안 바뀌는 것보다 매번 확실히 바뀌는 편이 낫다.**

폴백 테마도 `noborder_*` 에서 `light`/`dark` 로 바꿨다. `noborder_dark` 는 상자 배경이
`#1e1e20` 이라 우리 순수 검정과 거의 붙어 상자가 구분되지 않고 글자도 10.5:1 로 흐리다.
`dark` 는 글자가 16:1 이고 테두리가 있다 — 폴백에서는 우리 결보다 읽히는 것이 먼저다.

## 남는 문제

- giscus 테마 CSS 의 색은 `tokens.css` 를 손으로 옮긴 사본이라 토큰이 바뀌면 같이 고쳐야 한다.
  `pnpm check:contrast` 는 이 파일을 보지 않는다
- 올라온 댓글의 클래스(`.gsc-comment` 계열)는 실제 댓글이 달린 화면에서 다시 확인해야 한다.
  지금 규칙은 giscus 소스의 이름을 따랐고, 없으면 무해하게 무시된다
