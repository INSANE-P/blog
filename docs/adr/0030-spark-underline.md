# ADR-0030: 링크 밑줄은 번개가 지나가듯 그어진다

- 상태: 채택
- 날짜: 2026-09-05
- 관련: ADR-0024(시각 정체성), ADR-0029(표지와 내용의 언어)

## 배경

내비와 워드마크에 마우스를 올렸을 때 글자색만 바뀌었다. 틀리지는 않지만 어느 사이트에나 있는
반응이라 이 사이트의 것으로 읽히지 않았다.

참고한 것은 [jeong-min.com](https://jeong-min.com) 이다. 실제 구성을 들여다보니 단순한데
영리한 데가 하나 있었다.

```css
a::after      { transform: scaleX(0); transform-origin: right bottom; }
a:hover::after{ transform: scaleX(1); transform-origin: left  bottom; }
```

호버 여부에 따라 `transform-origin` 이 뒤집힌다. 들어올 때는 왼쪽에서 자라고 나갈 때는
오른쪽으로 빠져서, 선이 커졌다 작아지는 것이 아니라 **왼쪽에서 오른쪽으로 지나가는** 것으로 보인다.

## 결정

### 곧은 선 대신 스파크가 튀는 선

우리 히어로의 장치는 채움↔비움 대비(`PARK` 솔리드 / `CHANBIN` 아웃라인)인데, 작은 글자에서는
쓸 수 없다 — 1px 아웃라인 획은 20px 아래에서 뭉갠다. 같은 성격(없던 것이 생겨난다)을 선으로 옮겼다.

네 가지를 실제 크기로 렌더해 비교했다.

| 후보 | 결과 |
| --- | --- |
| 곧은 선 | 깔끔하지만 특징이 없다 |
| 촘촘한 물결 | **맞춤법 검사 밑줄로 읽힌다** |
| 얕게 흔들리는 손그림 선 | 부드럽지만 전기 느낌이 없다 |
| **평평하다 이따금 튀는 선** | **채택** |

대부분 평평하고 가끔 날카롭게 튀는 편이 "불규칙하지만 그 안에서 정돈된" 쪽에 맞았다.
스파이크는 급하게 오르고 완만하게 내려온다 — 대칭이면 톱니로 보인다.

### 모양은 mask, 색은 background-color

데이터 URI 안에 색을 박으면 라이트·다크에 각각 한 벌씩 둬야 한다. 모양만 `mask` 로 넣고
색은 `background-color: var(--accent-text)` 로 주면 한 벌로 두 테마를 덮는다.
타일을 `repeat-x` 로 반복시키므로 글자가 길든 짧든 스파크 간격이 같다.

### 원점 뒤집기는 쓰지 않는다

`transform-origin` 뒤집기는 `scaleX` 를 전제로 하는데, 우리 밑줄은 모양이 있어서 `scaleX` 로
늘리면 스파크가 가로로 찌그러진다. 그래서 `clip-path` 로 드러낸다 — 모양은 그대로 두고
가림막만 걷힌다. 대신 나갈 때는 왔던 쪽으로 되돌아간다.

애니메이션 두 벌(들어올 때/나갈 때)로 뒤집기를 흉내 낼 수는 있지만, 첫 렌더에 "나가는"
애니메이션이 한 번 재생돼 밑줄이 잠깐 번쩍인다. 눈에 띄는 결함을 감수할 만한 차이가 아니다.

### 지금 보고 있는 페이지는 밑줄을 켜 둔다

활성 표시가 굵기와 색뿐이라 약했다. 밑줄을 켜 두면 "여기에 있다"가 한눈에 읽힌다.

### 워드마크의 점은 브랜드 색으로 되돌린다

ADR-0027에서 글자용 악센트(`--accent-text`)를 도입할 때 일괄 치환이 과하게 먹어,
워드마크와 히어로의 점까지 어두운 글자색으로 바뀌어 있었다. 점은 글자가 아니라 그림이라
브랜드 색(`--accent`)이 맞고, 그림 요소 기준 3:1 을 통과한다.

### 글 끝 반응 버튼을 없앤다

로그인 없이 남길 수 있다는 점이 이 버튼의 존재 이유였지만, 글 끝이
`keep reading` → `comments` 로 이어지는 흐름에서 가운데 놓인 버튼 하나가 리듬을 끊었다.
반응이 없을 때 비어 보이는 것도 사실이다. 댓글이 이미 그 자리를 맡는다.

`StokeButton`·`actions.ts`·`Entry.stokes`·조회 컬럼을 함께 지웠다 —
화면에서 지운 것은 코드에서도 지운다(ADR-0028에서 얻은 교훈).

## 결과

- `.spark-line` 하나로 워드마크·내비·푸터 링크·`all posts` 가 같은 밑줄을 쓴다
- 헤더 항목은 `data-here` 로 현재 페이지에 밑줄을 켜 둔다
- 반응 관련 코드 전부 삭제. DB 의 `stokes` 컬럼은 남아 있으나 아무도 읽지 않는다

## 남는 문제

- `stokes` 컬럼과 `increment_stokes` RPC 가 DB 에 남아 있다. 지우려면 마이그레이션이 필요한데,
  되돌릴 수 없는 작업이라 당장은 두고 본다
- 나갈 때 왔던 쪽으로 되돌아간다. 첫 렌더 번쩍임 없이 뒤집는 방법을 찾으면 그때 바꾼다
