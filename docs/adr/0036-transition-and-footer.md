# ADR-0036: 테마 전환의 병목과 푸터 간소화

- 상태: 채택
- 날짜: 2026-09-05
- 관련: ADR-0024(시각 정체성), ADR-0028(푸터 링크 열), ADR-0030(번개 밑줄)

## 테마 전환 — 저장을 전환 밖으로

전환 중간에 한 번 걸리는 느낌이 있다는 지적을 받고, 추측 대신 프레임 간격을 쟀다.
긴 글(절 14개 · 그림 14장)을 1440×900 에서 네 번씩 전환하며 `requestAnimationFrame` 간격을 기록했다.

| 조건 | 평균 | 최대 프레임 | 33ms 초과 |
| --- | --- | --- | --- |
| 620ms + 콜백 안에서 저장(기존) | 16.6ms | **29.3ms** | 0.8회 |
| 620ms + 저장 제외 | 16.3ms | 25.2ms | 0.3회 |
| 420ms + 저장 | 16.1ms | **21.4ms** | 0.3회 |
| 페이드(비교군) | 16.3ms | 25.4ms | 0.5회 |

애니메이션 자체는 60fps 를 유지했다. 차이는 **최대 프레임**에서 났다.

**`localStorage.setItem` 은 동기 디스크 쓰기다.** 전환 콜백 안에 두면 브라우저가 새 화면을 찍는
바로 그 프레임에서 쓰기를 기다린다. 값은 미리 알 수 있으므로 전환을 시작하기 전에 저장한다.

전환 시간도 0.62초 → 0.48초로 줄였다. `clip-path` 애니메이션은 합성 단계가 아니라
본 스레드에서 도는데, 길수록 그 사이에 다른 일이 끼어들 틈이 커진다.

아이콘 상태는 `flushSync` 로 콜백 안에서 즉시 반영한다. React 의 기본 갱신은 비동기라
그냥 두면 브라우저가 새 화면을 찍은 뒤에 아이콘이 바뀌어, 전환이 끝나고 나서 아이콘만
따로 바뀌는 것처럼 보인다.

## 푸터 — 사이트 지도가 아니라 마무리 인사

깊이가 목록 → 글 두 단계뿐이고 페이지가 둘뿐인데 푸터에 열을 나눠 링크를 늘어놓으면,
있지도 않은 구조를 흉내 내는 셈이 된다. 셋을 걷어냈다.

- **`pages` 열** — 붙박이 헤더가 항상 보여 주는 것을 한 번 더 적은 것이었다
- **열 제목(`pages`·`elsewhere`)** — 링크 셋에 붙인 제목은 없는 구조를 만든다
- **태그라인** — 히어로와 모바일 메뉴에 이미 있다. 세 번째는 반복이다

남은 것은 누가 썼는지(워드마크·저작권)와 밖으로 나가는 길뿐이고, 한 줄에 들어간다.

## 남는 문제

- 측정은 헤드리스 브라우저에서 했다. 실제 글 화면에는 giscus iframe 이 있어 스냅샷 비용이
  더 든다. 여전히 걸린다면 전환 중 iframe 을 잠시 감추는 방법을 본다

## 목차 앵커가 어긋나던 문제

목차가 자동 생성되는 방식을 설명하려고 코드를 다시 보다 버그를 찾았다.

목차는 **원문 마크다운**에서 `## ` 로 시작하는 줄을 뽑고(코드 펜스는 먼저 지운다),
제목 글자를 슬러그로 바꿔 `#앵커` 링크를 만든다. 본문의 `h2` 에도 같은 방식으로 id 를 단다.
서버에서 만들어 내려보내므로 자바스크립트가 늦게 와도 보이고 검색엔진에도 잡힌다.

문제는 **양쪽이 서로 다른 글자에서 id 를 만들고 있었다**는 것이다.

- 본문 쪽은 React children 을 `String()` 으로 바꿔 썼다. 제목에 굵게·인라인 코드·링크가 들어가면
  children 이 배열이 되고 그 안의 React 요소가 `[object Object]` 가 된다
- 목차 쪽은 원문에서 `*`·`_`·`` ` `` 만 걷어냈다. 링크 `[글자](주소)` 는 주소까지 남았다

결과적으로 **꾸밈이 든 제목은 목차를 눌러도 아무 데도 가지 않았다.**

| 제목 | 목차가 가리키던 곳 | 본문의 실제 id |
| --- | --- | --- |
| 첫 번째 절 | `첫-번째-절` | `첫-번째-절` |
| 노션 **정본** 이야기 | `노션-정본-이야기` | `노션-object-object-이야기` |
| `` `ON CONFLICT` 가 막히는 이유 `` | `on-conflict-가-…` | `object-object-가-…` |

양쪽을 **같은 글자**에서 만들도록 고쳤다. `plainText()` 가 링크·코드·강조 문법을 걷어내
사람이 읽는 글자만 남기고, 본문 쪽은 React children 대신 hast 노드에서 글자를 모은다.

일곱 가지 제목(평범·굵게·인라인 코드·링크·`snake_case`·기울임·중복)으로 확인했고
전부 일치한다. 코드 펜스 안의 `## ` 을 세지 않는 것과, 같은 제목이 두 번 나올 때
뒤에 번호가 붙는 것(`첫-번째-절-1`)도 함께 봤다.

## h2 앞의 표식을 걷어낸다

글줄 밖 여백에 악센트 사각형을 두었는데, 여백이 없는 좁은 화면에서는 숨겨야 했다.
**같은 글이 화면 폭에 따라 다른 모양이면 장치가 아니라 사고로 보인다.**
27px 굵은 글씨와 넉넉한 위 여백이면 절이 바뀐 것은 충분히 읽힌다.

## 덧붙임 (2026-09-05): 제목 옆 `#` 앵커를 없앴다

`h2` 에 마우스를 올리면 옆에 `#` 가 나타나던 것을 뺐다. id 는 그대로 두고 표시만 없앴다.

절 하나만 따로 공유하는 일은 개인 블로그에서 거의 없는데, 그 대가로 제목마다 호버할 때
기호가 튀어나와 읽는 흐름을 끊었다. 문서 사이트에서는 절 단위 링크가 자주 쓰여 값을 하지만
여기는 처음부터 끝까지 읽는 글이다.

링크가 필요하면 목차에서 절을 눌러 주소창에 남은 것을 복사하면 된다 —
양쪽이 같은 id 를 쓰므로 결과가 같다.
