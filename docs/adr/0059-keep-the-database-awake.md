# ADR-0059: 캐시를 잘 만든 대가로 DB 가 잠든다

- 상태: 채택
- 날짜: 2026-09-06
- 관련: ADR-0045(캐시 가능한 읽기), ADR-0058(화면이 쓰는 것만 읽는다)

## 배경

Supabase 무료 요금제는 **1주일 활동이 없으면 프로젝트를 멈춘다.**

우리 공개 화면은 전부 정적으로 굽고 한 시간마다 확인한다(ADR-0045).
그런데 재확인은 **요청이 있을 때만** 일어나고, 캐시가 맞으면 DB 를 아예 건드리지 않는다.

방문이 뜸한 주가 있으면 일주일 내내 질의가 한 번도 안 갈 수 있다.
그러면 프로젝트가 멈추고, 그 뒤 첫 동기화나 재생성이 실패한다. 손으로 깨워야 한다.

**캐시를 잘 만든 대가로 생긴 문제다.** 읽기를 아끼는 설계가 "활동 없음"으로 읽힌다.

## 결정

**하루 한 번 DB 를 아주 살짝 건드린다.**

```json
{ "crons": [{ "path": "/api/ping", "schedule": "0 4 * * *" }] }
```

Vercel 크론은 Hobby 에서 하루 한 번, ±59분 정확도까지 된다.
기준이 일주일이므로 여유가 크다 — 며칠 걸러도 잠들지 않는다.

## 깨우는 일이 요금제를 갉아먹으면 안 된다

앞뒤가 안 맞는 일이라, 값을 두 가지로 눌렀다.

**행을 읽지 않는다.** `head: true` 는 개수만 묻는다. 실제로 재 봤다.

```
본문 0B · 헤더 991B · 200
Content-Range: */0
```

한 번에 1 KB 가 안 된다. 월 30회면 약 30 KB — 한도 5 GB 의 **0.0006%** 다.

**화면을 재생성시키지 않는다.** 캐시된 페이지를 두드리면 ISR 이 돌아
오히려 목록 조회가 일어난다. 그래서 아무것도 그리지 않는 전용 경로를 뒀다.
깨우려다 전송량을 쓰는 것이 이 결정에서 가장 피하고 싶은 모양이었다.

Vercel 쪽도 월 30회 호출이라 Hobby 한도에 닿지 않는다.

## 열어 둔 이유

`CRON_SECRET` 을 넣으면 Vercel 이 크론 요청에 실어 보내고, 우리는 그것을 확인한다.
넣지 않아도 동작한다.

이 경로가 하는 일은 **발행된 글의 개수를 세는 것**뿐이고, 그 값은 목록 화면이 이미 보여 준다.
막을 것이 크지 않은데 처음부터 환경변수를 요구하면 배포가 한 단계 더 필요해진다.
나중에 넣으면 그때부터 막힌다.

## 실패는 실패로 돌린다

DB 가 이미 멈춰 있으면 이 질의도 실패한다. 그때 200 을 돌리면
**깨우는 장치가 고장난 것을 아무도 모른다.** 500 으로 돌려 크론 기록에 남긴다.

## 남는 것

이것은 무료 요금제의 성질을 우회하는 것이지 고치는 것이 아니다.
유료로 올리면 이 경로도 크론도 필요 없다. 그때 지우면 된다.
