# ADR-0047: 노션 블록을 어디까지 다룰 것인가

- 상태: 채택
- 날짜: 2026-09-05
- 관련: ADR-0022(노션 정본), ADR-0042(형광펜), ADR-0046(다루는 줄 알았던 태그)

## 배경

블록을 두루 쓴 글을 하나 만들어 실제 응답을 받아 봤다. 18종의 태그가 나왔다.

```
br · callout(color) · column(ratio) · columns · database(url,inline,data-source-url)
empty-block · file(src) · mention-date(start) · page(url) · pdf(src)
span(color,underline) · synced_block(url) · table(header-row) · table_of_contents(color)
td · tr · unknown(url,alt) · video(src,v)
```

**글자는 하나도 사라지지 않았다.** 보고에 뜬 것은 `empty-block` 과 `mention-date` 둘뿐이었다.

## 어디까지 다룰 것인가

노션 기능을 재현하는 것은 목표가 아니다. 목표는 하나다 — **글자가 조용히 사라지지 않는 것.**
그 기준으로 네 갈래로 나눈다.

**1. 반드시 다룬다 — 글자를 담는 블록**

문단·제목·목록·표·인용·콜아웃·토글·컬럼·동기화 블록. 여기서 놓치면 문장이 통째로 없어진다.
전부 다루고 있다.

**2. 링크로 충분하다 — 바깥을 가리키는 블록**

파일·PDF·동영상·오디오·북마크·임베드·하위 페이지·데이터베이스.
블로그에서 노션의 파일을 그대로 재생하거나 데이터베이스를 그리려면 노션을 화면에 이식해야 하는데,
그건 "노션을 정본으로 쓰되 화면은 우리 것"이라는 결정(ADR-0022)과 어긋난다.
주소로 남기면 필요한 사람은 눌러서 간다.

**3. 버리는 것이 맞다 — 노션 안에서만 뜻이 있는 것**

목차 블록(우리 목차가 이미 있다), 브레드크럼, 버튼, 빈 블록.
화면에 옮겨도 아무 일도 하지 못하는 것들이다.

**4. 값이 속성에만 있는 것 — 여기가 위험하다**

`<mention-date start="2026-09-05"/>` 가 그랬다. 자기 닫는 태그이고 **날짜가 속성에만 있다.**
껍데기를 벗기면 아무것도 남지 않아 "2026-09-05에 있었던 일" 같은 문장이 깨진다.

이 갈래는 손실 검사에도 안 잡힌다. 글자를 세는 검사는 태그 **안의 글자**를 보는데,
여기는 값이 태그 밖(속성)에 있기 때문이다.

## 결정

세 가지를 고쳤다.

- **날짜 멘션** — `start` 를, 기간이면 `start ~ end` 를 글자로 남긴다
- **빈 블록** — 조용히 버린다. 잃을 글자가 없으므로 보고할 것도 없다
- **빈 콜아웃** — 통째로 버린다. 노션에서 콜아웃을 만들고 글을 안 쓰면 `<empty-block/>` 하나만
  들어오는데, 그대로 두면 화면에 빈 인용문 찌꺼기가 남는다

**콜아웃 아이콘은 실물에서 속성이 아니라 내용으로 온다**(`<callout color="blue_bg">🍏</callout>`).
그래도 `icon` 속성 경로를 지우지 않았다 — 하나만 믿었다가 형광펜을 통째로 잃은 적이 있다.

**사람·페이지 멘션은 손대지 않았다.** 실물을 못 봤고, 짐작으로 적으면 형광펜 때와 같은 일이 벌어진다.
보고에 이름이 뜨면 그때 실물을 보고 정한다.

## 더 중요한 것 — 목록을 늘리는 것보다 시끄럽게 구는 것

노션은 앞으로도 새 블록을 낸다. 지원 목록을 아무리 늘려도 그때마다 뒤진다.
그러니 **"다 지원한다"가 아니라 "안 되면 조용히 사라지지 않는다"** 를 지킨다.

그 장치가 실제로 일했다. `mention-date` 는 우리가 존재조차 몰랐던 태그인데,
"다루는 줄 알았던 태그" 보고(ADR-0046)가 잡아 줬다.
형광펜은 그 장치가 없어서 몇 주를 모르고 지났다.

새로 넣은 검사도 같은 성격이다 — 픽스처를 먼저 넣으면 고치기 전에 실패로 뜨고,
그 실패가 고쳤다는 증거가 된다.
