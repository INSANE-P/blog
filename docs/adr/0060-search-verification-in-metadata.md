# ADR-0060: 소유 확인 토큰도 메타데이터다

- 상태: 채택
- 날짜: 2026-09-06
- 관련: ADR-0044(검색 노출), ADR-0055(검색 결과의 이름)

## 배경

사이트맵·robots·구조화 데이터·RSS 를 만들어 뒀는데(ADR-0044) **아무 데도 제출하지 않았다.**
새 도메인은 가만두면 크롤러가 한참 뒤에나 찾아온다. 만든 것이 일을 하려면 등록이 필요하다.

등록하려면 먼저 소유를 확인시켜야 한다. 네이버 서치어드바이저부터 넣는다 —
한국어로 쓰는 블로그라 유입이 여기서 더 클 수 있다.

## 결정

**파일이 아니라 메타 태그로 둔다.**

```ts
verification: {
  other: { "naver-site-verification": "…" },
},
```

네이버는 HTML 파일 업로드를 권한다. 다만 그건 "head 를 고칠 수 없는 사이트"를 위한
대안이고 우리는 해당하지 않는다.

메타 태그로 두면 **사이트가 스스로를 설명하는 것들과 한자리에 모인다.**
Next 의 `verification` 필드가 그 자리이고, 구글 서치 콘솔 토큰이 생기면 같은 블록에 들어간다.
파일 방식은 루트에 정체를 알 수 없는 파일 하나가 남고,
그 값이 무엇인지가 코드 어디에도 적히지 않는다.

## 숨기지 않는다

이 토큰은 **비밀이 아니다.** 파일이든 메타 태그든 공개된 자리에서 읽히도록 설계된 값이다.
그래서 환경변수로 빼지 않고 소스에 그대로 둔다.

숨기는 시늉을 하면 다음 사람이 비밀인 줄 알고, 진짜 비밀과 같은 취급을 하게 된다.
`SYNC_SECRET` 이나 서비스 키와 이것은 다른 종류다.

## 남는 것

토큰을 넣는 것과 등록되는 것은 다른 일이다.
**배포된 뒤에 서치어드바이저에서 소유확인을 눌러야 하고, 사이트맵도 따로 제출해야 한다.**
코드가 할 수 있는 것은 여기까지다.

구글 서치 콘솔은 아직 넣지 않았다. 같은 자리에 한 줄 더 적으면 된다.
