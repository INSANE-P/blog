# ADR-0046: 그림의 폭, 그리고 "다루는 줄 알았던" 태그

- 상태: 채택
- 날짜: 2026-09-05
- 관련: ADR-0035(본문 폭과 삐져나감), ADR-0042(형광펜), ADR-0022(노션 정본)

## 그림이 본문 밖으로 나가던 문제

배포된 글에서 그림이 글줄 폭을 넘어가 있었다. 그림은 **943×754**, 5:4 다.
거의 정사각형인데 "넓게 낼 그림"으로 분류돼 좌우로 88px 씩 삐져나갔다.

규칙이 이랬다.

```ts
const tall = size.h > size.w * 1.15;
data-fit = tall ? "tall" : "wide"
```

**세로가 더 길지 않으면 전부 넓게.** 그러면 정사각형도, 4:3 도, 5:4 도 다 넓어진다.

### 넓게 낼 만한 그림은 가로로 긴 것뿐이다

16:9(1.78) 짜리 화면 캡처나 파노라마는 좁히면 안이 안 보인다. 넓힐 값이 있다.
4:3 이나 5:4 는 넓혀도 얻는 것이 없고 **자리만 크게 먹는다** —
글을 읽다 말고 큰 덩어리를 만나는 꼴이 된다.

그래서 갈래를 셋으로 나눴다.

| 갈래 | 조건 | 폭 |
|---|---|---|
| `tall` | 세로 > 가로 × 1.15 | 360px, 가운데 |
| `wide` | 가로 ≥ 세로 × 1.7 | 본문 밖으로 (최대 52rem) |
| `normal` | 그 사이 전부 | 본문 폭 |

경계를 1.7 로 둔 이유는 **16:9(1.78) 는 넘고 3:2(1.5) 는 못 넘는 자리**여서다.

### 원래 폭보다 크게 늘리지 않는다

`--nat` 으로 그림의 실제 가로 크기를 CSS 에 넘기고 상한에 넣었다.
없는 화소를 만들어 낼 수는 없으므로, 늘리면 흐려지기만 한다.
520×300 짜리 파노라마는 `wide` 지만 520px 로 멈춘다.

네 경우를 브라우저에서 재서 확인했다(본문 656px 기준).

```
normal 943×754   → 656px, 좌우 삐져나감 0
wide   1600×900  → 832px, 좌우 88px 씩 대칭
wide    520×300  → 520px (안 늘림), 가운데
tall    600×900  → 360px, 가운데
```

## "다루는 줄 알았던" 태그

형광펜을 잃은 사건(ADR-0042)의 교훈을 코드에 남긴다.

변환기는 `HANDLED` 에 없는 태그를 만나면 이름을 보고한다. 그런데 **거기 넣어 둔 태그는
보고에서 빠진다.** 다루기로 해 놓고 다루는 방법이 틀렸으면 조용히 사라진다.
형광펜이 정확히 그랬다 — `span` 을 목록에 넣고 `_background` 로 짐작했는데,
노션은 `_bg` 를 냈고, 짐작이 틀렸다는 사실조차 보고되지 않았다.

같은 함정이 세 군데 더 있었다.

- 동영상·소리·PDF·파일 → `src` 만 읽음
- 하위 페이지·데이터베이스 → `url` 만 읽음
- 북마크·임베드 → `url` 만 읽음

노션이 속성 이름을 하나만 바꿔도 **링크 없는 맨 글자**가 된다. 조용히.

### 두 가지로 막는다

1. **주소를 찾을 때 이름 하나만 보지 않는다.** `src` → `url` → `href` 순으로 본다
2. **다루기로 해 놓고 못 다룬 경우를 보고한다.** `video(주소 없음)` 처럼 보고에 실린다.
   동기화 응답에 그대로 나오므로 눈에 띈다

검사에도 넣었다 — 속성 이름이 `url` 이나 `href` 여도 링크가 되는지,
주소가 아예 없을 때 보고가 나가는지.

## 확인한 범위 — 한계도 적어 둔다

실제 노션 응답을 받아 훑었다. 지금 글에 나오는 태그는 다섯 종류뿐이었다.

```
span(color, underline) · br · table(header-row) · tr · td
```

전부 처리되고 **글자 손실 0**(원문 낱말 89개 중 사라진 것 없음).

다만 **이 글이 쓰지 않는 블록은 확인할 방법이 없다.** 콜아웃·토글·컬럼·수식·북마크 같은 것은
픽스처로만 검증했고, 노션의 실제 표기와 다를 수 있다 — 형광펜이 그랬듯이.

그래서 위의 "못 다루면 보고한다"가 중요하다. 다음에 어긋나면 **조용히 사라지지 않고
동기화 응답에 이름이 뜬다.** 블록을 두루 쓴 글을 한 번 만들어 동기화해 보면 더 확실하다.
