# ADR-0063: 노션 블록 사이에 빈 줄을 넣는다

- 상태: 채택
- 날짜: 2026-10-20
- 관련: ADR-0022(노션 정본), ADR-0062(코드 블록)

## 맥락

글 하나의 마지막 절이 통째로 굵은 h2 로 보였다. 들여다보니 그 절만의 문제가 아니었다.

노션 마크다운 엔드포인트는 블록 하나를 한 줄로 내고, **블록 사이에 빈 줄을 두지 않는다.** 실물을 받아 보니 208줄짜리 글에 빈 줄이 한 줄뿐이었다. 마크다운에서 문단을 나누는 것은 빈 줄이라, 이어진 문단이 전부 한 문단으로 붙었다. 줄바꿈은 띄어쓰기로 바뀌어 화면에서는 문단 경계가 사라졌다.

| 발행한 글 | 문단이 붙은 곳 | 문단이 제목이 된 곳 |
| --- | --- | --- |
| 연재 1~6편 | 편마다 11~19곳 | 편마다 1곳 |
| 7편, 체다, 하루치 | 9~19곳 | 0 |

제목이 된 것은 마크다운의 setext 규칙 때문이다. 문단 바로 다음 줄에 `---` 가 오면 그 문단을 h2 로 읽는다. 끝맺음 구분선 위 문단들이 붙은 채로 제목이 됐고, 목차에도 문단 전체가 올라갔다. 그림도 앞 문단 안으로 들어가 있었다.

노션 문법 검사(`pnpm check:notion`)는 이걸 잡지 못했다. 검사 예시가 블록 사이에 빈 줄이 다 들어 있는, 실물과 다른 모양이었기 때문이다.

## 결정

변환 마지막 단계(`htmlToMarkdown`)에서 블록 사이마다 빈 줄을 넣는다. 붙어 있어야 뜻이 사는 줄만 그대로 둔다.

| 그대로 붙여 두는 것 | 이유 |
| --- | --- |
| 표 줄끼리 | 빈 줄이 끼면 표가 끊긴다 |
| 목록 항목끼리 | 빈 줄이 끼면 목록 전체가 느슨해져 항목 사이가 벌어진다 |
| 인용문 줄끼리 | 한 인용문이다 |
| 줄 끝이 공백 두 개인 줄과 그다음 줄 | `<br>` 로 이은 한 문단이다 |
| 코드 블록, 수식 블록 안 | 글자 그대로여야 한다. 코드는 자리표로 빼 둔 뒤에 처리한다 |

목록 밖에서 들여쓴 줄은 들여쓰기를 걷어 낸다. 토글과 컬럼 안 내용이 탭으로 들여써서 오는데, 앞에 빈 줄이 생기면 마크다운은 네 칸 들여쓴 줄을 코드 블록으로 읽는다. 목록 항목 아래 들여쓴 그림과 설명은 그 항목의 자식이라 들여쓰기를 지킨다.

## 이유

- 렌더러가 아니라 변환기에서 고친다. 노션 마크다운을 우리 마크다운으로 되돌리는 일은 원래 변환기 몫이고(ADR-0022), 저장된 본문이 표준 마크다운이어야 다른 곳(RSS, 검색, 요약)에서도 같은 문단으로 읽힌다
- 실물 아홉 편을 고치기 전후로 해석해 견줬다. 줄바꿈이 낀 문단은 모두 0이 됐고, 제목 수는 노션 원문의 제목 줄 수와 같아졌다. 들여쓰기로 생긴 코드 블록은 0이다
- 그림이 있는 따라 하기 목록은 느슨한 목록이 된다. 항목 사이가 조금 벌어지지만, 그림과 설명이 항목 안에서 제 문단을 가진다

## 대안

- **줄바꿈을 그대로 줄바꿈으로 그리기(remark-breaks).** 붙은 문단이 줄은 나뉘어 보이지만 여전히 한 문단이라 문단 간격이 없고, `---` 위 문단이 제목이 되는 문제는 그대로다
- **모든 줄 사이에 빈 줄.** 표와 목록이 깨진다
- **노션 블록 API 로 블록을 하나씩 받아 직접 마크다운 만들기.** 정확하지만 ADR-0022 에서 피한 변환기 직접 구현으로 돌아간다

## 결과

- 동기화하면 발행한 글 아홉 편이 원래 문단대로 나뉜다
- `pnpm check:notion` 에 실물과 같은 모양(빈 줄 없음)의 예시를 더했다. 문단 나눔, 구분선 위 문단, 목록, 표, `<br>`, 코드, 토글 안 들여쓰기를 본다
- 남은 위험(따로 다룬다): 본문의 `<낱말>` 이 태그로 지워짐, `$` 두 개가 수식이 됨, 주소 바로 뒤 한글 조사가 링크에 붙음, `1)` 이나 `2026. 10.` 으로 시작하는 줄이 목록이 됨
