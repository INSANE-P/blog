# ADR-0023: 이미지 실물은 Cloudflare R2에 두고, 동기화 때 한 번 굽는다

- 상태: 제안됨
- 날짜: 2026-09-04

## 맥락 (Context)

[ADR-0022](0022-notion-as-source-of-truth.md)로 글의 정본이 노션으로 간다. 노션 본문의 이미지는 **서명된 URL이라 한 시간 정도면 만료된다.** 그대로 저장하면 며칠 뒤 글의 이미지가 전부 깨진다.

기존 이미지 저장은 Supabase Storage 공개 버킷이었다([ADR-0017](0017-image-upload-storage.md)). 다만 그 결정은 **에디터에서 사용자가 업로드하는 흐름**을 전제로 했고, 그 에디터가 사라진다. 노션 이미지를 가져와 저장하는 파이프라인은 어느 쪽을 쓰든 새로 만들어야 한다. 즉 지금이 저장소를 다시 고를 수 있는 시점이다.

무료 한도를 비교하면 이렇다.

| | Supabase Storage | Cloudflare R2 |
| --- | --- | --- |
| 저장 | 1GB | 10GB |
| 전송(egress) | 월 5GB | **없음(무제한)** |
| 호환 | Supabase SDK | S3 호환 |

## 결정 (Decision)

- **이미지 실물은 Cloudflare R2 버킷에 둔다.** 본문에는 공개 URL만 표준 마크다운(`![](url)`)으로 남긴다.
- **동기화 시점에 한 번만 처리한다.** 노션 이미지를 받아 → 긴 변 1600px로 축소하고 WebP로 변환 → R2에 올리고 → 마크다운의 URL을 R2 주소로 치환한다.
- **키는 내용 해시로 정한다.** 같은 이미지를 다시 동기화해도 다시 올리지 않는다(멱등).
- **서빙은 커스텀 도메인(`img.chanbin.dev`)으로 한다.** `r2.dev` 기본 주소는 Cloudflare가 프로덕션용이 아니라고 명시하고 스로틀이 걸린다. 개발 중에는 `r2.dev`를 쓰되, 공개 전에 커스텀 도메인을 붙인다.
- **요청 시점 변환은 하지 않는다.** 발행 때 이미 최적화된 파일을 굽는다.

## 이유 (Rationale)

- **전송량 절벽이 사라진다.** Supabase의 월 5GB는 넉넉하지만 여전히 한도이고, 글 하나가 퍼지면 그 달에 막힌다. R2는 egress 개념이 없어 트래픽을 예측할 필요가 없다.
- **R2의 약점이 이 설계에서는 문제가 되지 않는다.** R2에는 온디맨드 이미지 변환이 없지만, 우리는 발행 시점에 미리 굽기 때문에 필요하지 않다. 덤으로 Vercel 이미지 최적화 할당량에도 의존하지 않게 된다.
- **전환 비용이 낮다.** 어차피 새로 만드는 파이프라인이라, 기존 코드를 버리고 옮기는 것이 아니다.
- **Supabase 일시중지 위험에서 이미지가 분리된다.** 무료 프로젝트는 일정 기간 요청이 없으면 중지되는데, 이미지가 다른 곳에 있으면 그 영향에서 벗어난다.
- **S3 호환이라 다시 옮기기 쉽다.** 업로드 지점을 한 곳으로 모아두면 저장소 교체는 그 함수만 바꾸는 일이 된다.

## 고려한 대안 (Alternatives)

- **Supabase Storage 유지** — 이미 계정과 SDK가 있어 단순하다. 하지만 전송량 한도가 남고, 무엇보다 새 파이프라인을 어차피 짜야 해서 "이미 있다"는 이점이 실제로는 크지 않다.
- **노션 이미지를 프록시로 중계** — 경도 블로그가 쓴 방식. 만료 문제는 풀리지만 요청마다 노션을 거치고, 노션이 느리면 이미지가 느려진다.
- **레포에 이미지 커밋** — 의존이 없지만 레포가 무거워지고, 모바일에서 글 쓰는 흐름과 맞지 않는다.
- **Cloudflare Images(유료 변환 상품)** — 온디맨드 변환이 필요 없으므로 과하다.

## 결과 (Consequences)

**좋아지는 것**
- 전송량 걱정 없이 이미지를 쓴다
- 이미지가 만료되지 않는다
- 요청 시점에 변환이 없어 응답이 단순하고 빠르다

**감수하는 것**
- 서비스가 하나 늘어난다(Cloudflare 계정·버킷·키 관리)
- 공개 전에 **`chanbin.dev` 네임서버를 Cloudflare로 옮겨야** 커스텀 도메인을 붙일 수 있다. 이 이전은 `portfolio`·`resume` 서브도메인 레코드를 함께 옮기는 작업이라 따로 다룬다.
- 이미지 삭제 정리(고아 이미지)는 다시 설계해야 한다. [ADR-0020](0020-unused-image-sweep.md)의 방식은 에디터 업로드를 전제로 했다.

**후속 작업**
1. R2 버킷 생성, S3 호환 키 발급
2. 업로드 어댑터(내용 해시 키, 멱등)
3. 축소·WebP 변환 단계
4. 동기화에서 URL 치환
5. 공개 전 커스텀 도메인 연결
