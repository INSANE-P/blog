# ADR-0061: 발행 전 글은 나만 보는 미리보기로 확인한다

- 상태: 채택
- 날짜: 2026-10-18
- 관련: ADR-0022(노션이 정본), ADR-0044(검색 노출), ADR-0045(쿠키 없는 읽기), ADR-0058(대표 이미지)

## 배경

노션에서 보이는 글과 이 블로그에서 보이는 글은 다르다.
줄바꿈이 문단이 되는 방식, 형광펜, 그림 크기와 캡션, 목차가 다르고,
커버가 없는 글은 본문 첫 그림이 맨 위에 16:9 로 잘려 한 번 더 나온다(ADR-0058).

그런데 실제 모습을 보는 길은 **발행 체크를 켜고 동기화하는 것**뿐이었다.
확인하려면 먼저 공개해야 하는 셈이다. 고칠 것을 발행한 뒤에 찾게 된다.

## 결정

**`/preview` 와 `/preview/<노션 페이지 id>` 를 둔다. 나만 열 수 있고, 밖에서는 없는 주소다.**

### 잠금: Next 의 Draft Mode

`/api/preview?secret=…` 이 비밀값을 확인하고 Draft Mode 쿠키를 켠다.
미리보기 페이지는 이 쿠키가 없으면 `notFound()` 를 부른다.

- 쿠키 값은 배포마다 바뀌는 서명값이라 흉내 낼 수 없고, httpOnly 라 스크립트가 못 읽는다.
  CMS 미리보기를 위해 프레임워크가 [이미 준비해 둔 장치](https://nextjs.org/docs/app/guides/draft-mode)라 직접 만들 이유가 없다
- 비밀값이 틀리면 401 이 아니라 404 를 준다. 잠긴 문이 있다는 사실부터 알릴 필요가 없다
- 비밀값은 동기화 토큰과 나눈다(`PREVIEW_SECRET`). 이 주소는 브라우저 기록에 남는데,
  같은 값을 쓰면 그 기록 하나로 동기화까지 부를 수 있다
- 32자보다 짧으면 없는 것으로 친다. 짧은 값을 넣은 채로 열려 있는 것보다 닫혀 있는 편이 낫다
- 잠금 확인은 레이아웃이 아니라 각 페이지에서 한다. 레이아웃은 화면을 옮겨 다닐 때
  다시 그려지지 않을 수 있다

### 읽기: 노션을 그 자리에서

공개 화면은 노션을 직접 읽지 않는다. 노션 장애가 곧 사이트 장애가 되기 때문이다(ADR-0022).
미리보기는 반대로 **노션을 바로 읽는다.** 나 혼자 보는 화면이라 그 걱정이 작고,
노션에서 고친 것이 동기화 없이 새로고침만으로 보인다는 이득이 크다.

DB 를 거치지 않으므로 공개 글을 지키는 RLS 와 쿠키 없는 익명 클라이언트(ADR-0045)는 그대로다.
초안을 읽으려고 공개 읽기 경로에 예외를 두지 않는다.

**본문은 동기화와 같은 변환을 거친다.** `htmlToMarkdown`, 유튜브 제목 붙이기,
대표 이미지 규칙(`firstImageOf`)까지 같다. 그림을 R2 로 옮기는 일만 하지 않는다.
노션 그림 주소는 한 시간 뒤 만료되지만, 미리보기는 그 안에 다시 읽는다.

**그리는 컴포넌트도 같다.** 공개 글 화면의 `PostArticle` 을 그대로 쓴다.
비슷하게 다시 그리면 둘이 조금씩 어긋나기 시작하고, 그러면 미리보기를 믿을 수 없다.
다른 점은 댓글 하나다. 댓글은 주소로 묶이므로, 미리보기 주소로 댓글 자리가 만들어지면 안 된다.

연동 토큰은 블로그 데이터베이스 밖의 페이지도 읽을 수 있다.
그래서 **페이지의 부모가 블로그 데이터베이스인지 확인하고**, 아니면 404 다.

### 발행하면 걸릴 것을 미리 알린다

화면 아래 띠에 슬러그가 비었는지, 날짜가 비었는지, 블로그가 모르는 노션 서식이 있는지 적는다.
슬러그가 없으면 동기화가 그 글을 건너뛰는데(ADR-0022), 지금은 발행한 뒤에야 알 수 있었다.
띠는 글 위가 아니라 화면 아래에 떠 있다. 글 위에 두면 본문이 밀려 발행했을 때와 다른 자리에서 시작한다.

## 검색엔진

미리보기는 색인되면 안 된다. 그런데 크롤러에게는 이 주소가 애초에 404 다.
쿠키 없이는 열리지 않고, 사이트맵에도 없다. 여기에 두 겹을 더한다.

- 페이지의 robots 메타: `noindex, nofollow, nocache`
- 응답 헤더 `X-Robots-Tag: noindex, nofollow, noarchive`. HTML 메타는 404 나 리다이렉트 응답에는
  붙지 않으므로, 들어가는 주소(`/api/preview`)까지 헤더로 막는다
- 같은 헤더 묶음에 `Cache-Control: private, no-store` 와 `Referrer-Policy: no-referrer` 를 붙인다.
  들어가는 주소는 비밀값을 쿼리에 담고 있어서, 다른 사이트로 넘어갈 때 실려 가면 안 된다

**robots.txt 로는 막지 않는다.** 막으면 크롤러가 주소를 열어 보지 않으므로 404 도 noindex 도 보지 못한다.
링크가 어딘가에 새면 내용 없이 주소만 색인될 수 있다.
[구글도 noindex 를 쓰려면 robots.txt 로 막지 말라고 한다.](https://developers.google.com/search/docs/crawling-indexing/block-indexing)
열어 보고 404 를 받게 두는 편이 확실하다. robots.txt 에 경로를 적으면 그 경로가 있다는 것을 알리는 셈이기도 하다.

## 고려했지만 안 한 것

- **DB 에 들어간 초안을 읽기**: 동기화가 초안도 `draft` 로 넣고 있어 데이터는 이미 있다.
  하지만 그걸 읽으려면 서비스 키를 쓰거나 RLS 에 예외를 열어야 하고, 고칠 때마다 동기화를 눌러야 한다.
  공개 경로의 보호를 건드리는 값에 비해 얻는 것이 적다
- **주소에 비밀값을 계속 달고 다니기**: 쿠키 없이 매 요청을 쿼리로 확인하면 비밀값이
  모든 링크와 기록에 퍼진다. 한 번 확인하고 쿠키로 바꾸는 편이 덜 샌다
- **로그인을 다시 들이기**: 관리자 로그인은 노션 전환 때 걷어냈다(ADR-0022). 혼자 보는 화면 하나 때문에
  세션과 쿠키 기반 클라이언트를 되살리면 공개 화면의 캐시까지 다시 위협한다(ADR-0045)

## 결과

- 노션 데이터베이스 맨 위에 `/api/preview?secret=…` 북마크를 둔다. 누르면 목록이 열린다
- Vercel 에 `PREVIEW_SECRET` 을 넣어야 운영에서 열린다. 넣지 않으면 미리보기는 닫혀 있다
- 배포가 바뀌면 쿠키 서명이 바뀌어 미리보기가 닫힌다. 북마크를 다시 누르면 된다
- 미리보기를 켠 브라우저에서는 공개 화면도 캐시 없이 그려진다. 다 보면 띠의 "끝내기"로 쿠키를 지운다
