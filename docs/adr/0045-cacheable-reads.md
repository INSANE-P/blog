# ADR-0045: 공개 읽기는 쿠키 없이 — 화면을 캐시할 수 있게

- 상태: 채택
- 날짜: 2026-09-05
- 관련: ADR-0022(노션 정본·인증 제거), ADR-0044(검색 노출), 이슈 #51

## 배경

`next build` 출력이 이랬다.

```
┌ ƒ /
├ ○ /about
├ ƒ /posts
├ ƒ /posts/[slug]
├ ƒ /rss.xml
└ ƒ /sitemap.xml
```

글을 읽는 화면이 **전부 동적**이었다. `/about` 만 정적인데, 거기만 DB 를 조회하지 않는다.

## 원인

`src/lib/supabase/server.ts` 의 클라이언트가 `cookies()` 를 불렀다.
Next 에서 `cookies()` 를 건드리면 그 화면은 무조건 동적이 된다.

쿠키가 필요했던 이유는 로그인 세션이었다. 그런데 **인증은 노션 전환 때 없어졌다**(ADR-0022).
저장소를 뒤져 확인했다 — 미들웨어가 없고, `auth.` · `getUser` · `getSession` 을 부르는 곳도 없다.
쓰기(동기화)는 이미 쿠키 없는 클라이언트로 서비스 키를 쓴다.

**아무도 쓰지 않는 세션 때문에 모든 화면의 캐시를 포기하고 있었다.**

대가는 이랬다.

- 크롤러가 올 때마다 DB 를 친다. 사이트맵을 제출하면 그 횟수가 는다
- TTFB 가 매번 DB 왕복만큼 늦다 — 검색 순위에 들어가는 지표다
- Supabase 요청·전송량이 방문 수만큼 는다
- `rss.xml` 에 걸어 둔 `revalidate` 가 **아무 일도 하지 않았다.** 동적 화면이라 무시된다

## 결정

### 읽기는 쿠키 없는 익명 클라이언트로

`src/lib/supabase/read.ts`. `@supabase/supabase-js` + 익명 키.
요청마다 만들지 않고 모듈에 하나 둔다 — 익명 읽기 전용이라 요청 사이에 남는 상태가 없다.

초안이 새지 않는 것은 **RLS 가 지킨다.** 코드의 `.eq("status", "published")` 는 그 위에 두른 한 겹이다.
정책과 질의 둘 다 걸러야 한 쪽이 잘못돼도 초안이 나가지 않는다.

바꾼 뒤 익명 키로 직접 확인했다.

```
익명으로 전체 조회 → [{"slug":"hello-notion","status":"published"}]
익명으로 초안만 조회 → []
익명으로 쓰기 시도 → 막힘: new row violates row-level security policy
```

`@supabase/ssr` 은 쓰는 곳이 없어져 지웠다.

### 글 화면은 빌드 때 미리 만든다

`generateStaticParams` 로 발행된 글을 전부 굽는다. 없으면 첫 방문자가 올 때마다 그 글을
처음부터 만드는데, **크롤러가 그 첫 방문자인 경우가 많다.**

목록에 없는 새 글도 계속 열린다 — Next 는 모르는 값을 만나면 그때 만들어 캐시한다.
빌드 시점에 못 박아도 발행이 막히지 않는다.

### 안전망 주기는 1시간

**이 값은 신선도를 지키는 주된 수단이 아니다.** 글이 바뀌는 경로는 노션 동기화 하나뿐이고,
동기화가 끝나면 `revalidatePath` 가 즉시 캐시를 버린다. 그래서 이 값이 쓰이는 때는
그 호출이 빠졌거나 실패했을 때, DB 를 손으로 고쳤을 때, 배포 직후 첫 요청뿐이다.

즉 **"어긋났을 때 얼마 만에 스스로 회복하느냐"** 를 정하는 안전망이다.

| 값 | 어긋났을 때 | 비용 |
|---|---|---|
| `false`(영구) | 영원히 낡은 채로 — 동기화 쪽 버그 하나가 사이트를 굳힌다 | 0 |
| 1일 | 최대 하루 | 거의 0 |
| **1시간** | 최대 1시간 | 경로당 시간당 렌더 1회 |
| 1분 | 최대 1분 | 경로당 분당 렌더 1회 |

ISR 은 만료돼도 사용자를 기다리게 하지 않는다 — 옛것을 주면서 뒤에서 다시 만든다.
그래서 짧게 잡아도 체감 손해는 없고 비용만 는다. 1시간이면 아무도 눈치채기 전에 회복되고,
`false` 는 버그 하나로 사이트가 영구히 굳는 구조라 쓰지 않는다.

바깥의 관행도 한 방향이다 — **발행 시점에 버리고, 시간 기반은 보험으로.**
정적 생성기는 발행할 때 다시 빌드하고(사실상 `false` + 온디맨드),
헤드리스 CMS 는 웹훅으로 버린다. 노션 기반 블로그들이 60~3600초로 짧게 잡는 것은
웹훅이 없어 **폴링에 기대기 때문**인데, 우리는 동기화를 직접 돌리므로 그 끝에 붙이면 된다.

### 캐시를 버리는 일은 캐시를 켜는 일과 한 몸이다

동기화 라우트에서 버리는 대상을 넓혔다.

- 홈·목록에 더해 **사이트맵과 피드** — 목록이 바뀌면 같이 바뀐다
- **지워진 글** — 안 그러면 노션에서 지운 글이 캐시에 남아 계속 열린다
- 바뀐 것이 없어 건너뛴 글은 버리지 않는다. 버릴 이유가 없다

## 결과

```
┌ ○ /                    1h
├ ○ /about
├ ○ /posts               1h
├ ● /posts/[slug]        1h
├ ○ /robots.txt
├ ○ /rss.xml             1h
└ ○ /sitemap.xml         1h
```

동적으로 남은 것은 동기화 라우트와 글별 OG 이미지뿐이다.

## 남는 것

동기화 뒤 화면이 즉시 바뀌는지는 배포 후 한 번 확인해야 한다.
`revalidatePath` 의 경로가 실제 라우트와 어긋나면 조용히 아무 일도 하지 않는다.
