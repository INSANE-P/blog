# ADR-0057: 빈 목록으로는 지우지 않는다

- 상태: 채택
- 날짜: 2026-09-06
- 관련: ADR-0022(노션 동기화), ADR-0053(내려간 글 확인), ADR-0044(검색 노출)

## 배경

동기화는 노션에 없는 글을 DB 에서 지운다. 노션이 정본이므로 맞는 규칙이다 -
남겨두면 노션에 원본이 없어 **고칠 수도 지울 수도 없는 유령 행**이 쌓인다.

문제는 그 규칙에 바닥이 없다는 것이다.

```ts
const gone = data.filter((r) => !livePageIds.includes(r.notion_page_id));
```

노션이 빈 목록을 주면 `livePageIds` 가 비고, **모든 글이 `gone` 이 된다.**
그런데 노션이 빈 목록을 주는 이유는 둘이고, 응답만으로는 구분되지 않는다.

- 정말로 글을 다 지웠다
- 노션이 잠깐 제대로 답하지 못했다(권한 일시 오류, 페이지네이션, 연결 끊김)

앞은 드물고 뒤는 흔하다.

## 무엇을 잃는가

겁을 실제보다 크게 잡으면 과한 장치를 만들게 되므로, 잃지 않는 것부터 적는다.

- **글 내용은 잃지 않는다.** 다음 동기화에서 노션에서 다시 만들어진다
- **날짜도 틀어지지 않는다.** 사이트맵·RSS 의 발행일은 `published_at` 이 아니라
  노션이 준 날짜를 쓴다(ADR-0044)
- **댓글도 산다.** giscus 는 경로로 묶여 있다

잃는 것은 **시간**이다. 잘못된 동기화부터 다음 동기화까지 모든 글이 404 다.
그 사이에 크롤러가 오면 색인에서도 빠진다.

그리고 **아무도 알아채지 못한다.** 응답은 200 이고 `removed` 에 조용히 목록이 담길 뿐이다.
ADR-0053 에서 초안이 두 시간 열려 있던 것을 못 본 것과 같은 종류의 침묵이다.

## 결정

**노션이 0개를 주면 아무것도 지우지 않고 실패로 응답한다.**

```ts
if (pages.length === 0 && !options.allowEmpty) {
  // DB 에 지울 것이 실제로 있을 때만 막는다
}
```

지울 것이 애초에 없으면(첫 배포 등) 막을 것도 없으므로 조용히 지나간다.
막을 때는 `removalBlocked` 에 몇 개를 지키고 멈췄는지를 적고, 응답을 500 으로 돌린다.

정말로 비울 때는 `?force=1` 을 한 번 더 누른다. 북마크에는 넣지 않는다 -
늘 켜져 있으면 장치가 없는 것과 같다.

### 0 만 막는 이유

**0 은 재앙과 오류가 겹치는 유일한 지점이다.** 마지막 글까지 지우는 일은 드물고,
API 가 빈 목록을 주는 것은 흔한 실패 모양이다. 그래서 여기만 막으면
거의 모든 사고를 잡으면서 정상 작업은 한 번도 막지 않는다.

**비율 기준은 넣지 않는다.** "절반 넘게 지우면 멈춤" 같은 것은 언젠가 정상적인 정리에서
걸린다. 그때부터 우회하게 되고, 우회가 습관이 되면 장치가 없는 것만 못하다.
막는 장치는 **거의 울리지 않아야 울렸을 때 사람이 본다.**

### 소프트 삭제를 하지 않은 이유

지우는 대신 `status: removed` 로 감출 수도 있었다. 그러지 않았다.

슬러그가 유니크라, 같은 슬러그로 글을 다시 만들면 감춰 둔 행과 부딪힌다.
그러면 "언젠가 진짜로 지우는" 일이 다시 필요해진다 - 문제는 풀리지 않고 미뤄진다.
게다가 복구 경로는 이미 있다. 노션 휴지통이 30일 보관하므로,
되살리려면 노션에서 복원하고 동기화를 한 번 돌리면 된다.

## 대가

정말로 전부 비우려는 사람은 한 번 더 눌러야 한다.
실제로 이 결정을 하게 만든 날, 글 두 개를 일부러 지운 상태였고
이 장치가 있었다면 그 동기화는 실패했을 것이다.

한 번 귀찮은 것과 조용히 사이트가 비는 것 중에서는 앞을 고른다.
**실패는 눈에 보이지만 조용한 삭제는 보이지 않는다.**
