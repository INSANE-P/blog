# ADR-0024: 시각 정체성을 포트폴리오와 하나로 합친다

- 상태: 제안됨
- 날짜: 2026-09-05

## 맥락 (Context)

지금 이 블로그는 자체 브랜드를 갖고 있다 — 설화/Frost 컨셉의 불꽃 로고([ADR-0001](0001-brand-and-logo.md)), 공룡 마스코트([ADR-0004](0004-mascot.md)), Gmarket 제목 폰트와 Frost 팔레트([ADR-0003](0003-typography-and-styles.md)).

문제는 **같은 사람의 사이트가 두 얼굴을 갖고 있다는 것**이다. 포트폴리오(`portfolio.chanbin.dev`)는 PARK CHANBIN 아웃라인 타이포와 순수 흑백 배경으로 만들어져 있고, 블로그는 하늘색 틴트에 불꽃과 공룡이 있다. 취업 과정에서 두 사이트를 함께 보게 되는데, 방문자가 같은 사람으로 인지하기 어렵다.

한편 두 사이트는 이미 **악센트 색을 공유한다.** 포트폴리오 CSS에 "블로그(frost-log)와 같은 팔레트. 강조는 이 색 하나만 쓴다"고 적혀 있다(`#2f8fb5`). 뿌리는 같은데 표현만 갈라진 상태다.

또 하나. 블로그는 `lucide-react`에서 아이콘 12종을 가져다 쓰지만, 포트폴리오는 **아이콘 라이브러리를 쓰지 않고** 필요한 SVG를 직접 그린다. 파비콘도 붓 터치로 흘려 쓴 P에 악센트 획 하나를 얹은 손그림이다.

## 결정 (Decision)

**블로그의 시각 정체성을 포트폴리오 쪽으로 통합한다.** 별도 브랜드 이름이나 마스코트를 두지 않는다.

- **버린다**: 불꽃 로고, 공룡 마스코트(`DinoMascot`·`DinoScene`·`DinoSpeech`·`FlameLogo`), Frost 틴트 배경, Gmarket 제목 폰트
- **가져온다**: 순수 흑/백 배경, 악센트 하나(`#2f8fb5` / 다크 `#5fcdee`), Montserrat 제목 + Pretendard 본문, `stroke-text` 아웃라인 타이포, `word-break: keep-all`, 붓 터치 P 파비콘 계열
- **아이콘은 직접 만든다.** `lucide-react` 의존을 걷어내고, 쓰는 아이콘만 SVG로 그려 `components/icons/`에 둔다. 규격을 하나로 고정한다 — 24×24 viewBox, 1.5 stroke, `currentColor`, round cap/join, fill 없음
- **블로그이기 때문에 포트폴리오와 달라지는 부분**은 읽기 경험에 쓴다(아래 별도 항).

## 블로그가 포트폴리오와 달라야 하는 것

포트폴리오는 **훑어보는** 곳이고 블로그는 **읽는** 곳이다. 같은 토큰을 쓰되 다음은 블로그 고유로 둔다.

| 항목 | 값 | 근거 |
| --- | --- | --- |
| 본문 폭 | 40자 이하(약 34rem) | ★ WCAG 1.4.8 — 한중일은 40자 이하 |
| 본문 행간 | 1.8 | ★ WCAG 1.5 이상 + 한글은 베이스라인이 낮아 더 넓게 |
| 본문 크기 | 18px (모바일 17px) | △ 읽기 목적 관행 |
| 정렬 | 왼끝맞춤 | ★ justify 는 한글 어간을 파괴한다 |
| 등장 애니메이션 | **본문에는 쓰지 않는다** | 읽는 중에 문단이 나타나면 방해가 된다. 목록·홈에만 |

★ = 표준·논문 근거 / △ = 관행

## 이유 (Rationale)

- **한 사람으로 읽히게 하기 위해서다.** 포트폴리오·이력서·GitHub 프로필이 이미 같은 타이포 정체성을 쓴다. 블로그만 다른 얼굴이면 연결이 끊긴다.
- **유지할 브랜드가 하나로 준다.** 마스코트를 가진다는 것은 상황마다 그 캐릭터를 그려야 한다는 뜻이다. 혼자 만드는 블로그에서 그 비용은 계속 쌓인다.
- **아이콘을 직접 그리면 정합성을 통제할 수 있다.** 라이브러리 아이콘은 굵기·여백·모서리 처리가 제각각이라, 몇 개만 써도 미세하게 어긋난다. 규격을 하나로 정해 직접 그리면 그 문제가 사라지고 번들에서 의존성 하나가 빠진다.
- **색을 하나만 쓰는 규율이 이미 검증됐다.** 포트폴리오가 악센트 하나로 충분히 동작하고 있다.

## 고려한 대안 (Alternatives)

- **지금 브랜드 유지, 색만 맞추기** — 마스코트를 살릴 수 있지만 두 얼굴 문제가 그대로 남는다. 절반만 통합하면 오히려 어중간하다.
- **블로그에 새 이름·로고를 만든다** — 정체성이 셋이 된다. 유지 비용이 늘고 연결은 더 약해진다.
- **`lucide-react` 유지** — 당장은 편하다. 다만 포트폴리오와 아이콘 문법이 갈리고, 라이브러리 아이콘끼리도 굵기가 미묘하게 다르다. 쓰는 아이콘이 12종뿐이라 직접 그리는 비용이 크지 않다.
- **마스코트만 남기고 로고는 통합** — 공룡이 어디에 등장할지 규칙을 다시 정해야 하고, 절제된 타이포 위에 캐릭터가 얹히면 톤이 충돌한다.

## 결과 (Consequences)

**좋아지는 것**
- 포트폴리오·이력서·GitHub·블로그가 하나의 얼굴이 된다
- 색·타이포·아이콘 규칙이 한 벌로 줄어든다
- `lucide-react` 의존성이 빠진다

**감수하는 것**
- **되돌리기 어렵다.** 마스코트와 불꽃 로고에 들인 작업(ADR-0001·0004)을 폐기한다
- 아이콘을 직접 그려야 한다. 새 아이콘이 필요할 때마다 규격에 맞춰 만드는 손이 든다
- 개성이 옅어질 수 있다. 절제된 타이포만으로 인상을 남겨야 한다

**대체되는 ADR**: [0001](0001-brand-and-logo.md)(브랜드·로고), [0003](0003-typography-and-styles.md)(타이포), [0004](0004-mascot.md)(마스코트), [0006](0006-layout-and-theme-transition.md)(레이아웃) 일부

## 덧붙임 (2026-09-05): 바깥 링크 표시를 ↗ 에서 사슬로 바꿨다

밖으로 나가는 링크 옆에 `↗` 를 붙여 왔다. "여기서 나간다"까지 말해 주는 표시지만,
글자 옆에 화살표가 서면 글줄이 자꾸 오른쪽 위로 튀어 읽는 결이 끊겼다.

사슬은 방향을 말하지 않는 대신 글줄에 얹혀 있어 조용하다.
나가는지는 새 탭이 열리는 것으로 알 수 있다. 잃는 것보다 얻는 것이 크다고 봤다.

도형은 고리 둘을 **떼어 놓고** 사이를 대각선으로 잇는다.
실제 사슬처럼 겹쳐 그렸더니 13px 에서 획이 서로 닿아 덩어리가 됐다.
본문 글자 옆에 붙는 자리라 획도 1.5 가 아니라 1.8 로 굵혔다 —
1.5 는 15px 아래에서 실처럼 흐려진다. 그래서 `Svg` 에 `strokeWidth` 를 열어 뒀다.

본문 안의 링크는 아이콘 컴포넌트를 쓸 수 없으므로 같은 도형을 `mask` 로 넣고
색은 `currentColor` 로 받는다. 링크 색이 바뀌면 아이콘도 따라간다.

`ArrowUpRight` 는 쓰는 곳이 없어져 세트에서 뺐다.
