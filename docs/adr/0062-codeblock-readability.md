# ADR-0062: 코드 블록 안쪽을 읽히게 다시 잡기

- 상태: 채택
- 날짜: 2026-10-20
- 관련: ADR-0027(글 읽는 화면과 색 기준)

## 배경

지표 대시보드 연재를 발행하고 코드 블록을 보니 세 군데가 어긋나 있었다.

1. **줄마다 상자가 따로 생겼다.** `.prose code` 는 문장 속 짧은 코드에 배경, 테두리, 안쪽 여백을 준다. 이 규칙이 블록 안의 `code` 에도 걸려서, code 가 인라인으로 흐르며 줄이 바뀔 때마다 그 줄만 한 상자를 그렸다.
2. **글자가 상자 왼쪽 끝에 붙었다.** 여백을 code 가 갖고 pre 는 0이었다. 첫 줄과 나머지 줄의 시작점도 달랐다.
3. **언어 이름이 `plain` 으로 나왔다.** 노션이 붙이는 내부 이름을 그대로 보여 줬다. 발행한 글의 코드 블록 32개 가운데 21개가 이 이름이었다.

줄 간격도 본문 값(18px, 1.85)을 물려받아 코드 줄 사이가 벌어져 있었다.

## 결정

### 블록에서는 code 가 모양을 벗고, 여백은 pre 가 맡는다

`.prose .codeblock pre code` 에서 배경, 테두리, 여백, 둥근 모서리를 지운다. 선택자를 `.prose code` 보다 구체적으로 둬서 순서와 상관없이 이긴다.

### 글자 크기와 줄 간격은 본문보다 작게

| | 글자 | 줄 간격 | 안쪽 여백 |
| --- | --- | --- | --- |
| [GitHub 마크다운](https://github.com/sindresorhus/github-markdown-css) | 본문의 85% | 1.45 | 16px |
| [Tailwind Typography](https://github.com/tailwindlabs/tailwindcss-typography) | 본문의 0.875em | 약 1.71 | 약 0.86em 1.14em |
| 바꾼 값 | 14.5px(본문 18px의 약 80%) | 1.7 | 16px 20px 18px |
| 휴대폰(640px 이하) | 13.5px | 1.7 | 14px 16px 16px |

코드는 한 줄씩 훑고 들여쓰기로 구조를 본다. 줄 사이가 벌어지면 위아래 줄의 관계가 끊겨 보인다. 그렇다고 너무 좁히면 한글 주석이 답답해져서 두 레퍼런스의 사이인 1.7로 뒀다.

### 긴 줄은 접지 않고 가로로 넘긴다

API 주소처럼 긴 줄이 많다. 접으면 들여쓰기가 어디서 시작했는지 흐려지고, 복사해 쓸 줄이 화면에서 두 줄로 보인다. `code` 를 `width: max-content` 로 두어 가로 스크롤 안에서 배경이 끊기지 않게 했다.

### 코드 속 한글은 프리텐다드로

`--font-mono` 의 고정폭 글꼴들(Consolas 등)에는 한글이 없어서, 한글 주석이 운영체제 기본 글꼴로 빠졌다. `monospace` 앞에 `var(--font-pretendard)` 를 넣어 본문과 같은 한글이 나오게 했다. 영문과 숫자는 그대로 고정폭이다.

### 언어 이름은 읽는 사람이 아는 이름으로

`typescript` → `TypeScript`, `bash` → `Shell`, `json` → `JSON` 처럼 바꿔 보인다. `plain`, `text` 같은 일반 글자 블록은 이름을 비운다. "이게 무슨 언어지"에 답하지 못하는 이름은 없는 편이 낫다. 머리 줄은 위아래 여백을 줄여 코드보다 눈에 덜 띄게 했다.

## 대안

- **긴 줄 접기(`white-space: pre-wrap`).** 휴대폰에서 가로 스크롤이 사라지지만, 접힌 줄이 들여쓰기 없이 맨 앞에서 다시 시작해 구조가 흐려진다. 주소 한 줄이 두세 줄로 보여 복사할 범위도 헷갈린다.
- **하이라이트 테마 라이브러리 통째로 쓰기.** 색이 토큰마다 달라져 ADR-0027에서 정한 네 갈래 색 원칙과 부딪힌다. 문제는 색이 아니라 상자와 여백이었다.
- **언어 이름 대신 파일 이름 보여 주기.** 노션 코드 블록에는 파일 이름 칸이 없어 쓸 수 없다.

## 결과

- 줄마다 생기던 상자가 사라지고 왼쪽 시작선이 하나로 맞는다
- 라이트와 다크 모두 같은 토큰(`--code-bg`, `--code-bar`, `--prose-fg`)을 쓴다. 색은 바꾸지 않았다
- 인라인 코드 모양은 그대로다
