# ADR-0029: 내비게이션은 영문, 내용은 한글

- 상태: 채택
- 날짜: 2026-09-05
- 관련: ADR-0024(시각 정체성), ADR-0025(읽기 중심 구조), ADR-0026(목록·헤더)

## 배경

헤더 항목이 `글` / `소개` 였다. 그런데 같은 줄의 워드마크는 `CHANBIN.` 이고, 히어로는
`PARK CHANBIN` 이며, 주소도 `/posts` · `/about` 이다. 껍데기는 이미 영문 활자로 돌아가는데
내비만 한글이라 한 줄 안에서 문법이 한 번 끊겼다.

라이트·다크 두 벌을 나란히 렌더해 비교했다. 한글 쪽은 워드마크와 내비가 서로 다른 문자와
서체를 써서 "두 시스템이 한 줄에 있는" 것처럼 보였고, 영문 쪽은 한 덩어리로 읽혔다.

## 결정

### 껍데기는 영문, 내용은 한글

- **껍데기**(워드마크·내비·푸터 링크 이름) — 영문, 몬세라트
- **내용**(페이지 제목·섹션 제목·본문·안내 문구) — 한글

ADR-0026에서 섹션 머리말을 작은 영문 라벨(`RECENT -`)에서 큰 한글(`최근 글`)로 바꾼 것과
어긋나 보이지만 대상이 다르다. 그건 **읽는 화면 안의 내용**이었고 이건 **길을 가리키는 표지**다.
표지는 짧고 반복해서 보는 것이라 활자 정체성을 지는 자리로 알맞고, 내용은 읽으라고 있는 것이라
읽는 사람의 말이어야 한다.

이 방식은 한국 개인 블로그에서 흔한 구성이기도 하다 — 내비는 `posts about guestbook`,
본문은 한글.

### 소문자로 쓴다

워드마크가 대문자 900 이라 내비까지 대문자면 둘이 서로 크기를 다툰다.
소문자로 두면 워드마크가 주인공이고 내비는 조용한 이정표가 된다.

### 라벨은 주소와 같은 말로

`posts` → `/posts`, `about` → `/about`. 주소창에 보이는 말과 화면에 보이는 말이 같으면
링크를 복사해 공유했을 때도 어디인지가 그대로 읽힌다.

### 글 상세에 돌아가기 링크를 두지 않는다

깊이가 목록 → 글 두 단계뿐이라 되돌아갈 길은 붙박이 헤더의 `posts` 하나로 충분하다.
글 맨 위에 두면 읽기 시작하기도 전에 나가는 문부터 보게 만든다.
다 읽은 뒤의 갈 곳은 아래 이어 읽기가 맡는다(피크엔드 법칙, ADR-0025).

## 결과

- `NAV` 라벨이 `posts` · `about` 으로 바뀌고, 헤더·모바일 메뉴·푸터가 함께 따라간다
- 헤더 항목에 `font-display`(몬세라트)를 준다. 이 줄은 화면에서 유일하게 영문만 있는 자리라
  서체까지 맞춰야 한 덩어리로 읽힌다
- 모바일 메뉴는 46px 몬세라트 소문자. 큰 활자 두 개가 화면의 주인이 된다
- 페이지 제목(`글`)과 본문은 그대로 한글이다 — 표지에서 내용으로 넘어오는 지점이다

## 남는 문제

- 항목이 셋 이상으로 늘어나면 영문 라벨이 길어져 헤더가 빡빡해질 수 있다.
  그때는 라벨이 아니라 항목 수를 다시 본다(ADR-0025)
