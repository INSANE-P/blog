# ADR-0042: 노션 형광펜을 살린다

- 상태: 채택
- 날짜: 2026-09-05
- 관련: ADR-0012(원시 HTML 미실행), ADR-0030(번개 밑줄), ADR-0027(본문 읽기)

## 배경

긴 글에서 눈이 쉴 곳을 만드는 장치다. 노션에서 색을 입혀 놓아도 화면에서는 **그냥 평문이었다** —
강조한 사실이 통째로 사라지고 있었다. 콜아웃이 사라지던 것과 같은 종류의 손실이다.

### 노션 쪽

색 입힌 글자가 어떤 모양으로 넘어오는지 한 가지로 확정할 수 없어 셋을 다 받는다.

- `<mark>글자</mark>`
- `<span color="yellow_background">글자</span>`
- `<highlight>글자</highlight>`

전부 `==글자==` 로 옮긴다. **글자색만 바꾼 것**(`color="blue"` 처럼 `_background` 가 아닌 것)은
형광펜이 아니라 그냥 글자라 건드리지 않는다 — 껍데기만 벗기고 글자를 남기는 기존 경로로 간다.

실제로 무엇이 오는지는 동기화 뒤 "모르는 태그" 보고를 보면 알 수 있다.
셋을 다 `check:notion` 픽스처에 넣어 두었으므로 변환이 깨지면 검사가 먼저 잡는다.

### 렌더 쪽

마크다운 표준에는 형광펜이 없다. `==` 는 Pandoc·옵시디언이 쓰는 관례다.
원시 HTML 은 실행하지 않으므로(ADR-0012) `<mark>` 를 그대로 흘려보낼 수는 없고,
`==` 를 mdast 단계에서 노드로 바꾼다.

라이브러리를 쓰지 않고 직접 걷는다(`remark-highlight.ts`). 하는 일이 열 줄이라
의존성 하나와 그것이 끌고 오는 unist 유틸 묶음을 받을 이유가 없다.

두 가지가 이 구현의 핵심이다.

- **`text` 노드만 본다.** 코드는 `code`·`inlineCode` 라는 다른 노드에 담기므로
  코드 안의 `==` 는 애초에 이 함수를 지나가지 않는다. 따로 막을 필요가 없다
- **`emphasis` 에 `hName: "mark"` 를 얹는다.** mdast 에 없는 타입을 새로 만들면
  HTML 로 옮기는 단계에서 처리기가 없어 통째로 사라진다. 이미 처리기가 있는 타입에
  태그 이름만 바꿔 달면 자식이 그대로 살아서 `<mark>` 안에 들어간다

`unist` 타입은 import 하지 않고 필요한 모양만 파일 안에 적었다.
`unist` 는 remark 가 안으로 쓰는 패키지라 우리 `package.json` 에 없고,
pnpm 은 남의 의존성을 끌어다 쓰지 못하게 막는다.

### 생김새 — 라이트와 다크가 다른 모양이다

형광펜은 **흰 종이에 밝은 잉크를 얹는** 물건이다. 그 은유가 검은 화면에서는 뒤집힌다.
그래서 두 테마를 같은 모양으로 두지 않았다. 이 저장소가 "라이트는 다크를 뒤집은 것이 아니다"를
지켜 온 것과 같은 이유다.

**라이트 — 글자 아래 절반만 덮는다.**

```css
background: linear-gradient(to top, var(--mark) 0, var(--mark) 46%, transparent 46%);
```

상자를 다 칠하면 줄 사이가 붙어 단락이 색 덩어리로 보이고, 문장 안에서 어디까지가
강조인지도 흐려진다. 아래만 덮으면 글자는 배경 위에 그대로 앉아 있고 표시만 지나간다 —
이 사이트에서 밑줄이 하는 일과 같은 문법이다(ADR-0030).
기울기가 아니라 딱 끊기는 두 칸짜리 그라데이션이다. 번지면 잉크가 아니라 그림자로 보인다.

**다크 — 잉크를 끝까지 밝히고 글자를 검게 뒤집는다.**

처음에는 다크도 같은 띠로 두었다. 그런데 검은 화면에서 옅은 띠는 "칠했다"가 아니라
**"어둡게 깔았다"로 읽힌다.** 형광펜인지 알아볼 수 없었다.

띠만 밝히면 될 것 같았는데, 재 보니 그 길이 막혀 있었다.

| 잉크 알파 | 띠 색 | 흰 글자 | 본문색 | 검은 글자 |
|---|---|---|---|---|
| 0.26 (처음) | #19353e | 12.96 | 9.97 | 1.62 |
| 0.45 | #2b5c6b | 7.38 | 5.67 | 2.85 |
| 0.55 | #347183 | 5.47 | 4.21 | 3.84 |
| 0.72 | #4494ab | **3.46** | 2.66 | 6.07 |
| 1.00 | #5fcdee | 1.83 | 1.41 | **11.45** |

밝은 글자를 유지하면서 띠를 형광펜처럼 밝힐 수는 없다. 0.72 부터 흰 글자가 기준(4.5)을
밑돈다. **대비와 은유가 같은 방향을 가리키는 선택지는 하나뿐이었다** —
잉크를 끝까지 밝히고 글자를 검게 뒤집는 것. 11.45:1 로 이 사이트에서 가장 잘 읽히는 조합이다.

```css
.dark .prose mark { background: var(--mark); }  /* --mark: var(--accent), --mark-fg: #000 */
```

색은 토큰 두 개(`--mark`·`--mark-fg`)로만 갈리고 규칙은 한 벌이다.
대비는 `check:contrast` 가 지킨다 — 라이트 13.81:1, 다크 11.45:1.

그 김에 검사기가 `var(--다른-토큰)` 참조를 따라가도록 고쳤다.
`--mark-fg: var(--prose-fg)` 처럼 값을 손으로 옮겨 적지 않으려고 둔 참조인데,
검사기가 그걸 못 읽으면 참조를 쓰지 말라는 압력이 된다.

### 왜 노란 형광펜이 아닌가

이 사이트에 노랑이 없다. 악센트 하나로 밑줄·진행·현재 위치·형광펜을 다 말하면 색이 늘지 않는다.
