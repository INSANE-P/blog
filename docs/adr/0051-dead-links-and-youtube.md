# ADR-0051: 독자가 갈 수 없는 곳은 링크로 만들지 않는다

- 상태: 채택
- 날짜: 2026-09-05
- 관련: ADR-0022(노션 정본), ADR-0047(블록 범위), ADR-0045(캐시)

## 배경

블록을 두루 쓴 글을 변환해 보니 **독자에게 나가는 링크 10개 중 7개가 죽어 있었다.**

```
정상  https://chanbin.dev/
죽음  bookmark  → app.notion.com/p/...
정상  https://www.youtube.com/watch?v=...
정상  (이미지 — R2 로 옮겨짐)
죽음  file://%7B%22source%22...  (파일)
죽음  file://%7B%22source%22...  (PDF)
죽음  file://%7B%22source%22...  (동영상 ×2)
죽음  내부 페이지 → app.notion.com/p/...
죽음  표보기     → app.notion.com/p/...
죽음  button    → app.notion.com/p/...
```

두 갈래다.

- **노션에 올린 파일·PDF·동영상** — `file://%7B%22source%22%3A%22attachment%3A...` 라는
  노션 앱 내부 참조로 온다. 브라우저에서 아예 열리지 않는다.
  게다가 라벨이 없어 **그 1000자짜리 주소가 링크 글자로 본문에 박혔다**
- **하위 페이지·데이터베이스·북마크·버튼** — `app.notion.com/p/<페이지>#<블록>` 으로 온다.
  그 페이지가 공개가 아니면 로그인 요구나 404 다

## 북마크 카드는 만들 수 없다

노션처럼 제목·설명·썸네일이 있는 카드를 그리려 했지만, **재료가 오지 않는다.**

```
<unknown url="https://app.notion.com/p/3d25...#3d25..." alt="bookmark"/>
```

`alt` 는 제목이 아니라 **블록 종류 이름**(`bookmark`, `button`)이고,
`url` 은 **노션 내부 주소**다 — 북마크가 실제로 가리키는 바깥 주소가 아니다.

그래서 제목도, 설명도, 파비콘을 뽑을 도메인도 없다.
바깥 페이지를 긁어 채우는 방법조차 쓸 수 없다 — **긁을 주소가 없기 때문이다.**

## 결정

**독자가 눌러서 갈 수 있는 곳만 링크로 만든다.**

- `file://` 로 시작하면 링크를 만들지 않는다
- `notion.com` · `notion.so` 호스트면 링크를 만들지 않는다

### 그래도 글자는 남긴다

링크를 버리되 **이름은 남긴다.** 주소 안에 `attachment:<uuid>:<파일이름>` 이 들어 있어
파일 이름은 꺼낼 수 있다.

글이 "아래 영상을 보면" 으로 이어지는데 그 자리에 아무것도 없으면 문장이 끊긴다.
받을 수 없는 파일이라도 **"여기 이 파일이 있었다"** 는 맥락은 값이 있다.

다만 라벨이 블록 종류 이름(`bookmark` · `button`)뿐이면 남길 것이 없으므로 버린다.

### 무엇을 왜 버렸는지 보고한다

`file(노션에 올린 것이라 링크를 만들 수 없음)` · `page(노션 안에서만 열림)` 처럼
동기화 응답에 담는다.

**"주소가 없음" 과 "못 여는 주소" 를 나눠 적는다.** 앞은 우리가 속성 이름을 못 찾은 것이고
(고칠 수 있다), 뒤는 노션이 원래 주지 않는 것이다(고칠 수 없다).
같은 통에 담으면 고칠 수 있는 것을 못 알아본다.

## 유튜브는 임베드한다

`<video src="https://www.youtube.com/watch?v=...">` 는 **진짜 주소로 온다.**
링크로만 두면 아무도 누르지 않으므로 영상으로 그린다.

### 누르기 전에는 그림 한 장

`<iframe>` 을 바로 심으면 유튜브 스크립트 묶음이 문서와 함께 내려온다 —
한 편에 1MB 가까이 되고, 읽기만 하고 재생하지 않는 사람이 대부분인데 그 값을 모두가 치른다.

그래서 썸네일과 재생 단추를 우리가 그리고, 누른 뒤에야 `<iframe>` 을 끼운다.
안 누르면 비용은 이미지 하나다. 캐시를 켜고 TTFB 를 줄여 온 방향(ADR-0045)과 같은 이야기다.

`youtube-nocookie.com` 을 쓴다. 재생하기 전까지 유튜브는 방문자를 알 수 없다.

재생 단추는 유튜브의 빨강이 아니라 우리 악센트로 그린다 —
이 화면에 빨강은 어디에도 없어서 혼자 튄다.

### 변환기는 링크만 내놓는다

"무엇으로 보일지" 는 화면이 정한다. 문단이 유튜브 링크 하나뿐이면 영상으로 바꾼다 —
그림에서 쓰던 규칙과 같다. 화면이 없어도 마크다운은 링크로 읽히고,
글 속에 섞여 들어온 유튜브 링크는 건드리지 않는다(문단이 두 동강 난다).

주소 파서는 JSX 밖(`youtube-id.ts`)에 둔다. JSX 가 있으면 node 로 바로 못 읽어
검사 스크립트가 돌려 볼 수 없기 때문이다. 네 가지 주소 모양을 검사에 넣었다.

## 결과

```
전:  링크 10개 중 7개 죽음
후:  링크 3개, 죽은 것 0개, 유튜브 1개는 영상으로
     버린 것 7건은 전부 보고됨
```
