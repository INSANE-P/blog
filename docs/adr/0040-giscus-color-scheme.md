# ADR-0040: 댓글 iframe 의 바닥 색을 OS 가 아니라 우리 테마에 묶는다

- 상태: 채택
- 날짜: 2026-09-05
- 관련: ADR-0021(giscus 댓글), ADR-0028(커스텀 테마 CSS), ADR-0037(댓글 상자)

## 배경

다크 모드에서 댓글이 통째로 보이지 않았다. 배경도 테두리도 없이 새까맣고,
회색 글자 한 줄과 textarea 오른쪽 아래 리사이즈 손잡이만 남았다.
같은 증상을 두 번 고쳤는데 두 번 다 재발했다 — 원인을 잘못 짚었기 때문이다.

## 무엇이 실제로 일어나는가

giscus 위젯을 실제로 띄워 iframe 안쪽 계산값을 읽어 확인했다. 원인은 사슬이었다.

1. giscus 에 테마 CSS **주소**를 넘긴다.
2. iframe 이 그 주소를 못 불러온다. 개발 중에는 항상 그렇다 —
   giscus 는 https 이고 우리 개발 서버는 http 라 mixed-content 로 막힌다
   (`net::ERR_FAILED`). 배포 뒤에도 404·차단기·네트워크 실패로 같은 일이 생길 수 있다.
3. 그러면 `--color-fg-default` 를 비롯한 색 변수가 **하나도 정의되지 않는다**.
   giscus 자신의 CSS 는 전부 이 변수를 참조하므로 색이 통째로 빠진다.
4. 남는 것은 브라우저 기본값인데, giscus 는 자기 shadow DOM 안에서
   `iframe { color-scheme: light dark }` 를 걸어 둔다. 그래서 안쪽 문서의 기본 글자색이
   **운영체제 설정**을 따른다. OS 가 라이트면 기본 글자색은 검정이다.
5. 우리 화면은 다크라 배경이 검정이다. 검은 배경에 검은 글씨 → 아무것도 안 보인다.

핵심은 4번이다. "우리 CSS 가 잘못됐다"가 아니라 "CSS 가 안 실렸고, 그때의 바닥 색이
우리 테마가 아니라 OS 를 따랐다" 였다. 그래서 라이트 모드에서는 우연히 멀쩡해 보였고
(흰 배경 + 검은 기본 글자) 다크 모드에서만 사라졌다.

커스텀 CSS 자체는 멀쩡하다. 같은 CSS 를 https 응답으로 가로채 주입했더니
상자·테두리·악센트 버튼이 의도대로 나왔다.

## 결정

두 겹으로 막는다.

1. **주소를 넘기기 전에 확인한다.** https 가 아니면 아예 시도하지 않고, 맞으면 파일이
   있는지 한 번 받아 본다. 없으면 giscus 내장 테마로 물러난다. (기존 결정, 유지)
2. **그래도 실패할 때를 대비해 iframe 의 바닥 색을 우리 테마에 묶는다.**

```css
giscus-widget::part(iframe) { color-scheme: light; }
.dark giscus-widget::part(iframe) { color-scheme: dark; }
```

`::part` 로 바깥에서 지정한 값은 shadow 안쪽 규칙을 이긴다 — 실제로 확인했다.
OS 가 라이트인 채로 테마 CSS 를 일부러 죽여도 안쪽 글자색이 흰색으로 계산됐다.

## 왜 2번이 필요한가

1번만으로는 "안 실릴 수 있는 경우"를 우리가 전부 알아야 한다.
mixed-content 는 예측할 수 있지만 차단기·CDN 실패·오탈자 난 경로는 예측할 수 없고,
실패했다는 사실을 iframe 바깥에서 읽을 방법도 없다(다른 출처다).

2번은 원인을 몰라도 결과를 막는다. 색은 잃더라도 글자는 읽힌다.
망가지는 방향이 "안 보임"에서 "덜 예쁨"으로 바뀌는 것이 이 결정의 전부다.

## 대가

테마 CSS 가 실패하면 giscus 기본 모양이 나온다. 우리 말풍선도 브랜드 색도 없다.
그건 받아들인다 — 안 보이는 것보다 낫고, 실패하지 않는 정상 경로에서는 아무것도 달라지지 않는다.
