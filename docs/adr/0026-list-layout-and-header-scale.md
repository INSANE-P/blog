# ADR-0026: 목록은 큰 커버 카드로, 헤더·활자는 한 단계 크게

- 상태: 채택
- 날짜: 2026-09-05
- 관련: ADR-0024(시각 정체성), ADR-0025(읽기 중심 구조)

## 배경

ADR-0024·0025 를 코드로 옮긴 뒤 화면을 처음 눈으로 확인했다. 결과가 좋지 않았다.
전체적으로 작고 답답하며, "직접 만든 것"이 아니라 "기본값을 조합한 것"처럼 보였다.

원인을 찾기 위해 실제로 잘 만들어진 한국 서비스의 목록 화면을 직접 열어 측정했다.

- 토스 기술 블로그(toss.tech): 헤더 약 60px, 목록 제목 약 18px, 우측 썸네일 약 137×94
- 당근 채용 콘텐츠: 커버가 카드 상단에 크게, 그 아래 제목 → 설명 → 태그

두 곳이 갈리는 지점이 있었고, 그 차이가 이번 결정의 핵심이었다.

## 결정

### 1. 목록은 커버가 위에 오는 카드로 한다

토스는 우측 썸네일, 당근은 상단 커버다. 둘 다 성립하지만 전제가 다르다.

우측 썸네일은 **글이 수십·수백 개 쌓인 목록**의 배치다. 한 화면에 더 많은 행을 넣어
훑어 내려가게 하는 것이 목적이고, 그래서 사이드바(인기 글·최신 댓글)까지 함께 둔다.
이 블로그에는 그런 양이 없다. 같은 배치를 쓰면 한 행이 얇아 목록이 비어 보이고,
글 하나하나의 무게가 사라진다.

커버를 위에 크게 두면 글 하나가 하나의 대상이 된다. 글이 적을 때 오히려 유리하다.
글이 수십 개로 늘어나면 그때 목록 페이지만 밀도 높은 행으로 바꾸면 된다 —
지금 없는 문제를 위해 지금의 화면을 희생하지 않는다.

커버가 없는 글도 같은 크기의 자리를 지킨다(제목 첫 글자를 크게 앉힌다).
있는 글만 커지면 목록의 리듬이 깨지고, 커버 유무가 곧 중요도로 잘못 읽힌다.

### 2. 치수를 한 단계 올린다

헤더 76px(모바일 68px), 내비 17px, 섹션 제목 32px, 카드 제목 22px, 컨테이너 1080px.
헤더가 얇고 글씨가 작으면 "어디로 갈 수 있는지"가 눈에 들어오지 않는다.
누르는 대상은 크게 둔다(피츠의 법칙).

### 3. 섹션 머리말은 작은 영문 라벨이 아니라 큰 한글 제목으로

포트폴리오는 훑어보는 화면이라 `RECENT -` 같은 작은 대문자 라벨이 맞다. 블로그는
읽으러 온 사람의 화면이고, 이 라벨은 그에게 읽히지 않는 장식으로만 남는다.
`최근 글` 처럼 큰 한글로 쓴다. 토스·당근 모두 이 자리에 영문 라벨을 쓰지 않는다.
작은 라벨은 소개 페이지처럼 항목을 훑는 화면에만 남긴다.

### 4. 워드마크는 큰 활자에서만 속을 비운다

아웃라인(`-webkit-text-stroke`)은 획이 굵을 때만 형태가 읽힌다. 히어로(48px 이상)에서는
2px 획으로 또렷하지만, 헤더의 22px에서는 실선만 남아 흐리게 번진다.
헤더·푸터·모바일 메뉴의 워드마크는 속을 채우고, 히어로만 아웃라인으로 둔다.

### 5. 테마 토글은 화려한 해와 별 하나로

후보를 실제 크기(21~24px)로 렌더해 놓고 골랐다. 화면을 보지 않고 정하면 지금까지처럼
"설명은 그럴듯한데 눈으로는 별로인" 것을 만들게 된다.

| 후보 | 결과 |
| --- | --- |
| 영문 라벨(DARK MODE) | 헤더 메뉴 옆에서 또 하나의 메뉴처럼 읽힌다 |
| 반차 원(◐) | 21px에서 회색 덩어리로 뭉갠다 |
| 조리개 | 개념은 정확하지만 24 그리드에 현 6개가 들어가지 않는다 |
| 코인(링↔원 뒤집기) | 정지 상태가 동그라미 하나라 조용하다 |
| 타원 궤도 + 중심별 + 행성 | **눈알로 보였다.** 타원 링에 가운데 점은 눈이다 |
| 기울어진 궤도 + 행성 + 꼬리 | 예쁘지만 밝기와 무관한 은유다 |
| 해 ↔ 별자리(점 여섯 개 재배치) | 별자리를 규칙적으로 두면 꺾은선 그래프로 읽힌다 |
| **화려한 해 ↔ 스파클 별 하나** | **채택** |

해/달을 쓰지 않겠다는 원칙에서 출발했지만, 문제는 소재가 아니라 그리는 방식이었다.
흔해 보이는 것은 해와 별이 아니라 "원 하나에 선 여덟 개"라는 기본형이다.

그래서 해는 광선을 열둘로 늘리고 길고 짧은 것을 번갈아 두었다. 길이가 모두 같으면
톱니바퀴로 보이고, 엇갈리면 빛이 뻗는 모양이 된다. 별도 정다각형이 아니라 변을 오목하게
당겨 끝이 가늘어지는 스파클로 그렸고, 작은 스파클 둘을 곁들여 균형과 깊이를 줬다.

색은 악센트 하나뿐 — 해의 몸통과 큰 별. 헤더에서 색을 가진 유일한 요소다(폰 레스토프 효과).

전환은 두 그림을 각각 회전·확대·투명도로 여닫는다. 서로 모핑하지 않는 이유는 광선 열둘과
스파클의 점 개수가 달라 중간 프레임이 반드시 뭉개지기 때문이다. 회전을 서로 반대로 줘서
갈아 끼우는 느낌이 아니라 하나가 돌아 다른 하나가 되도록 했다.
모션 최소화를 켠 사용자에게는 전환 없이 상태만 바뀐다.

### 6. 푸터는 실제로 존재하는 링크의 열로 채운다

원형 아이콘 버튼만 두면 어디로 가는지 눌러 봐야 알고, 본문과 떨어져 떠 보인다.
갈 곳이 셋뿐이라 이름을 그대로 쓰는 편이 빠르다. 비어 있던 세로 공간은 실제 링크로 채운다.
없는 메뉴로 열을 만들어 규모를 꾸미지는 않는다 — 눌러서 아무 데도 가지 않는 링크가
가장 값싼 인상을 준다.

## 결과

- `PostRow`(우측 썸네일 행) 삭제, `PostCard`(상단 커버) 신설. 홈과 목록이 같은 카드를 쓴다
- 홈·목록·소개·헤더·푸터의 가로폭을 1080px 로 통일해 좌측 정렬선이 화면 간에 맞는다
- `--surface-hover` 토큰 추가 — 선을 하나 더 긋지 않고 면으로만 눌린 느낌을 준다
- 해↔달 모핑 CSS(`animations.css`) 제거 — 토글이 아이콘 교체가 아니라 점의 이동이 되면서 필요 없어졌다

## 남는 문제

- 글이 30편을 넘으면 목록 페이지는 밀도 높은 행으로 다시 검토한다
- 커버 없는 글이 계속 늘어나면 첫 글자 자리표가 반복돼 보인다. 그때 다시 본다
