# ADR-0033: 전체 화면 덮개는 body 로 옮겨 그린다

- 상태: 채택
- 날짜: 2026-09-05
- 관련: ADR-0028(모바일 메뉴)

## 배경

모바일 메뉴를 열면 헤더 높이만큼만 검게 칠해지고 그 아래로 뒤 페이지가 그대로 비쳤다.
두 번 고쳤는데 두 번 다 원인이 아니었다.

1. 덮개 전체에 페이드를 걸어 열리는 동안 뒤가 비친다고 봤다 — 실제 문제이긴 했지만 원인은 아니었다
2. `h-dvh` 를 `h-full` 로 바꿨다 — 이것도 원인이 아니었다

세 번째에야 재 봤다. 같은 덮개를 위치만 바꿔 실제 크기를 측정했다.

| 덮개 위치 | 측정된 크기 |
| --- | --- |
| 헤더 안 | 390 × 67 |
| body 로 옮김 | 390 × 700 |
| 화면 | 390 × 700 |

## 결정

**`backdrop-filter` 를 가진 요소는 자기 자손의 `position: fixed` 기준점이 된다.**

헤더에 `backdrop-blur` 가 걸려 있어서, 그 안의 덮개는 `inset: 0` 이 화면이 아니라
**헤더 박스**를 가리켰다. 그래서 헤더 높이만큼만 칠해졌다.
`transform`·`filter`·`will-change` 도 같은 효과를 낸다.

덮개를 포털로 `document.body` 에 그린다. 여는 버튼은 헤더에 남고 덮개만 밖으로 나간다.
헤더에서 `backdrop-blur` 를 빼는 방법도 있지만, 그러면 스크롤할 때 헤더 뒤로 글이 비쳐
읽기가 어지러워진다 — 문제는 흐림 효과가 아니라 덮개의 위치였다.

`z-index` 는 60 으로 올린다. 포털로 나가면 헤더의 쌓임 맥락 밖이라 문서 최상위에서
겨루게 되고, 헤더(40)보다 확실히 위여야 한다.

## 결과

- `MobileNav` 의 덮개가 `createPortal(…, document.body)` 로 그려진다
- 서버 렌더에는 DOM 이 없으므로 마운트 이후에만 그린다

## 교훈

**추측으로 두 번 고치는 동안 한 번도 재 보지 않았다.** 화면이 이상하면 눈으로 보고 끝내지 말고
값을 재야 한다. `getBoundingClientRect()` 한 줄이면 첫 시도에 끝날 일이었다.
