# ADR-0056: 댓글창은 쉬는 상태만 칠하면 안 된다

- 상태: 채택
- 날짜: 2026-09-06
- 관련: ADR-0021(giscus 도입), ADR-0028(테마 색 맞춤), ADR-0040(색 구조 폴백), ADR-0041(방명록)

## 배경

방명록의 "댓글 등록" 단추가 초록으로 떠 있었다. 배포된 화면에서다.

처음에는 커스텀 테마가 아예 안 실린 줄 알았다. 그래서 재 봤다.

| 확인                | 결과                                                                               |
| ------------------- | ---------------------------------------------------------------------------------- |
| 배포된 CSS          | `200` · `text/css` · `Access-Control-Allow-Origin: *`                              |
| iframe 안의 링크    | `<link id="giscus-theme" href="…/giscus-guestbook-light.css">` — 마지막 스타일시트 |
| `main` 의 계산된 값 | `--color-btn-primary-bg: #277796` (우리 파랑)                                      |

**테마는 실려 있었다.** 그런데도 초록이었다.

## 원인

그 초록은 GitHub 초록(`#1f883d`)이 아니라 **`#94d3a2`** 였다.
giscus 내장 테마의 `--color-btn-primary-disabled-bg` 다.

빈 칸이라 단추가 비활성 상태였고, 우리는 그 색을 덮지 않았다.

```
덮은 것    bg · text · border · hover-bg
안 덮은 것  disabled-bg · disabled-text · disabled-border · selected-bg
           hover-border · shadow · inset-shadow · selected-shadow
```

`btn-primary` 가 읽는 토큰은 여덟인데 넷만 칠했다.
**쉬는 상태만 보고 끝냈다** — 그 상태에서는 잘 보였기 때문이다.

## 결정

**giscus 앱 CSS 가 읽는 토큰을 훑어서 채운다.**
`giscus.app/_next/static/css/*.css` 에서 `var(--color-btn-*|--color-input-*)` 를 뽑아
빠진 것을 전부 덮었다. 눌린 상태, 비활성 상태, 초점 테두리, 적는 칸까지.

**검사가 이것을 지킨다.** 목록에 있는 토큰이 하나라도 비면 `pnpm check` 가 실패한다.
giscus 가 새 상태를 쓰기 시작하면 이 목록은 낡는데, 그때는 화면에 남의 색이 보이므로
목록에 한 줄 더 적으면 된다. 사람이 눈으로 지키는 것보다 낫다.

## 경계선은 두 갈래다

대비를 재 보니 경계선이 라이트 1.38:1, 다크 1.79:1 이었다. 전부 기준 미달로 나왔다.
그런데 전부 3:1 로 올리는 것은 답이 아니다.

**분리선**은 흐려도 된다. 댓글 사이의 선이 안 보여도 무엇이 무엇인지는
글과 여백이 말해 준다. 우리 화면의 실선이 이미 그 두께이고, 댓글창만 진하면 거기만 튄다.

**컨트롤의 경계**는 다르다. 방명록의 점선 상자는 배경이 투명이라
**그 선이 사라지면 어디에 적는지를 알 수 없다.** WCAG 1.4.11 이 3:1 을 요구하는 것이 이쪽이다.

그래서 `--ours-control-border` 를 따로 두고 그것만 3:1 을 넘긴다 —
라이트 3.35:1, 다크 3.95:1. 나머지 선은 그대로다.

잴 필요가 없는 것에까지 기준을 걸면 실패가 늘고, 실패가 늘면 검사기를 안 보게 된다.

## 대비 검사가 댓글창까지 본다

댓글창은 iframe 안이라 우리 CSS 가 닿지 않는다. 색을 변수로 넘겨 줄 뿐이고,
그 값은 토큰에서 **손으로 옮겨 적은 것**이라 토큰을 고쳐도 따라오지 않는다.

그래서 검사기가 네 테마 파일도 같은 자로 잰다.
화면만 통과하고 댓글창을 놓치면 "검사는 통과했는데 실제로 읽기 힘든 자리가 남은" 상태가 된다.

## 로컬에서도 우리 색이 보이게

테마 주소를 **지금 열어 둔 화면이 아니라 배포된 곳**으로 바꿨다.

giscus 는 https 라, 개발 서버(http)의 주소를 넘기면 iframe 안에서 mixed-content 로 막힌다.
예전에는 그때 내장 테마로 물러났는데, 그러면 **로컬에서는 늘 남의 색만 보게 된다.**
화면을 로컬에서 확인하는 사람에게는 사실상 테마가 없는 것과 같았다.

배포된 CSS 는 `Access-Control-Allow-Origin: *` 로 나가므로 어디서 열어도 실린다.

대가는 하나다. **CSS 를 고치는 중에는 로컬에서도 배포된 版이 보인다.**
색을 만지는 중이라면 올리고 나서 봐야 한다. 그 대신 다른 모든 때에 제 모습이 보인다.

## 남는 것

비활성 색은 WCAG 대비 기준의 적용 대상이 아니다(1.4.3 이 비활성 컨트롤을 제외한다).
그래도 "눌리지 않는다"가 형태로 읽혀야 하므로 악센트를 옅게 깔았다.
읽히지 않을 만큼 옅으면 그것대로 문제라, 이 값은 눈으로 한 번 봐야 한다.
